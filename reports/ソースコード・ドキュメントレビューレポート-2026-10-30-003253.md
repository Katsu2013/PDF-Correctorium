## 3. ソースコードで確認した不備・修正候補

### 3.1 Release バイナリに診断・テスト用 CLI スイッチが残っている

- **該当ファイル**: `src/PdfCorrectorium.App/App.xaml.cs`
- **内容**: `--smoke-test`, `--render-test`, `--keyboard-test`, `--document-ui-test`, `--persistence-test`, `--diagnostic-delay-worker` など、多数の非対話テスト・診断用コマンドライン引数が `#if DEBUG` などで分離されず、Release ビルドにもコンパイルされています。
- **リスク**: 通常利用者には不要な攻撃面を広げ、かつ過去のセキュリティ監査（`docs/Security-Audit-Report-2026-10-14.md`）でも「低」リスクながら指摘されています。
- **推奨対応**: 診断用スイッチを `#if DEBUG` ブロックで囲むか、別の診断専用ビルド構成に分離してください。`StartupArgumentRouting.FilesTakePriority` による無効化だけでは不十分です。

### 3.2 ソースコード内に TODO/FIXME/HACK 等の目立ったコメントは少ない

- `src/PdfCorrectorium.App/Services/QpdfExecutableResolver.cs` 内の `#if DEBUG` による開発時フォールバックは意図的なものであり、Release では同梱バイナリ固定参照となっています。
- 大規模な TODO コメントや未完成コードは確認されませんでした。

### 3.3 機密情報・個人情報の有無

- API キー、パスワード、接続文字列、PFX/SNK ファイル等は **検出されませんでした**。
- `Environment.UserName` をログに出力する箇所は、診断ログマスキング処理により `<user>` に置換されています（`DiagnosticLog.cs`, `StartupDiagnostics.cs`）。
- ただし、**ドキュメント内**に `C:\Users\katsu\...` 形式の絶対パスが残っており、これは個人環境の開示になります（後述）。

## 4. ドキュメントで確認した不備・修正候補

### 4.1 README の公開バージョン表記とダウンロードリンクが最新スナップショットと不一致

- **該当ファイル**: `README.md`
- **内容**:
  - バッジ（line 8）とダウンロードリンク（line 29、line 320）は **v1.0.0-dev.199** を指しています。
  - リポジトリスナップショットは **v1.0.0-dev.270**（line 127）です。
- **影響**: dev.270 を一般公開する場合、利用者が旧ビルド（dev.199）をダウンロードしてしまいます。現行の最新ビルドを公開するのであれば、バッジ・リンク・説明文を dev.270 用に更新する必要があります。
- **推奨対応**:
  - `README.md` のバッジ URL、ZIP ダウンロードリンク、公開バージョン表記を `v1.0.0-dev.270`（または実際に公開するリリース番号）へ更新。
  - 配布版が dev.199 のままである意図であれば、本文中の「現在の配布バージョン」との整合性を明確にしてください。

### 4.2 ROADMAP.md の英語セクションが旧バージョンのまま

- **該当ファイル**: `ROADMAP.md`
- **内容**:
  - 日本語セクションでは「現在の実装機能 (v1.0.0-dev.199)」と記載されています（line 79）。
  - 英語セクションでは「Current Features (v1.0.0-dev.196)」（line 189）と、さらに古いバージョンが混在しています。
- **推奨対応**: 日本語・英語の両方を、現在のリポジトリスナップショット（dev.270）または公開版（dev.199）のいずれかに統一してください。

### 4.3 ドキュメント内に個人環境の絶対パスが残っている

- **該当ファイル**:
  - `wiki/Roadmap.md`（line 124, 132, 171, 193）
  - `docs/Security-Audit-Report-2026-10-09.md`（多数）
  - `docs/Security-Audit-Report-2026-10-14.md`（多数）
- **内容**: `file:///C:/Users/katsu/Documents/Codex/PDF-Correctorium/...` 形式のリンクが大量に使用されています。
- **影響**:
  - Windows ユーザー名 `katsu` およびローカルディレクトリ構造が公開されます。
  - 他の開発者・レビューアがそのリンクをたどれません。
  - 一般公開時のプライバシー・体裁上の問題になります。
- **推奨対応**: 絶対パスリンクを相対リンク（例: `../../src/PdfCorrectorium.App/...`）に置き換えるか、単にファイル名のみの記述に変更してください。

### 4.4 セキュリティ監査・署名関連ドキュメントは公開条件未達を適切に開示

- `docs/SECURITY-DESIGN.md`、`SECURITY.md`、`CODE_SIGNING.md`、`docs/Distribution-Operations.md` は、コード署名未実施、独立レビュー未実施、Store 登録未完了、脆弱性報告窓口未設定であることを明記しています。
- これらは公開可否を判断する上で重要な情報であり、現状では「一般公開準備中」という位置づけが正しく伝わっています。

## 6. 推奨対応（優先順位付き）

1. **公開条件の整備**
   - SignPath Foundation（または同等）への申請・承認、コード署名基盤の構築。
   - 独立したセキュリティレビューの実施と記録。
   - 非公開の脆弱性報告窓口（GitHub Private Vulnerability Reporting 等）の有効化。
   - Microsoft Store / 直接配布のパッケージ識別子・プライバシー方針の確定。

2. **ドキュメントの整備**
   - `README.md` のバッジ・ダウンロードリンク・バージョン表記を、実際に公開するリビジョン（dev.270 またはそれ以降）へ更新。
   - `ROADMAP.md` の日本語・英語セクションのバージョン表記を統一。
   - `wiki/Roadmap.md`、`docs/Security-Audit-Report-2026-10-09.md`、`docs/Security-Audit-Report-2026-10-14.md` 内の `file:///C:/Users/katsu/...` 絶対パスリンクを相対リンクに修正。

3. **ソースコードの攻撃面削減**
   - `App.xaml.cs` の診断・テスト用 CLI スイッチを `#if DEBUG` または診断専用の条件付きコンパイルで囲む。
   - 公開リリース前に `tools/TestReleaseReadiness.ps1` を実行し、署名・レビュー・依存関係チェックがパスすることを確認。

4. **リポジトリ状態の整理**
   - 公開対象となるソース・ドキュメントをコミットし、不要な未追跡ファイル（一時診断出力等）を整理。
   - `BuildPortable.ps1` により新しい日時付きフォルダへ発行し、`GetBuildVersion.ps1` でメタデータを検証。
