# 07-01 OCR仕様

<!-- CURRENT-RELEASE-SNAPSHOT -->
## 現行仕様（v1.0.0-dev.274・コミット前確認）

RapidOCRは選択した横書き行の再認識に対応。余白付きの単一認識結果、手修正、差分確認、適用時の文字幅調整を行う。明確な補完条件を満たす場合と訂正確認を分け、手修正・固定・変更中の古い結果を保護する。

資料別の正解語・同文字数訂正ルール・無視語と、類似語／密度の分析を共用する。明示的に自動許可したルールだけを自動適用し、頻度だけで正解と断定しない。NDLOCR-lite本体、未OCR範囲／ページ／PDF全体の検出と縦書き混在認識は未実装。文字方向を編集できることと、認識エンジンの縦書き対応は別。

## 現行実装

dev.238では分析自体を変えず、結果の基本列と詳細列を分離する。文字数外れ値の基本はページ・判定・文字列・文字数・目安文字数。密度比・寸法等は詳細切替で確認できる。キーワード幅・類似語も同じ規約とし、固定・修正不可・曖昧な候補の注意を隠さない。行・ソート・選択を保持し、切替で再分析や未保存化を行わない。[一覧別の設計](../../../../docs/List-Presentation.md)。

dev.237の文字数外れ値は、CJKを約1、欧文を基本0.6等へ幅換算し、行の縦横比で正規化した密度を比較する。書字方向と行の太さを揃え、独立した穏当な密度の中央値で文書内の字幅差を補正する。基準不足や中央50%が1.5倍を超えてばらつく場合、明示的な複数行・不正な枠は判定しない。Unicodeテキスト要素ごとに測り、結合記号を幅へ重複加算しない。目安文字数は対象行自身の文字種構成を使う。スライディング窓の順位統計で総当たりを避け、計算はUIスレッド外、途中キャンセル時は部分結果を返さない。実フォントの実測ではなく、複雑な組版を含め精度保証ではない。[式・基準・制約](../../../../docs/OCR-Character-Density.md)。

dev.236は文字数外れ値の表示だけをキャッシュ済み結果から絞り込む。位置／サイズ固定は初期非表示、文字固定のみは対象外。固定領域も統計の比較対象に含み、チェック変更で再分析しない。固定変更の履歴だけで現在の固定列と表示を更新し、通常の位置変更に候補一覧の再走査を加えない。

新規の範囲・ページ・PDF全体OCRは未実装。既存OCRを保持し、横書き・縦書き・混在を対象に、枠・方向・読み順をプレビュー確認してから一括追加する方針は確認済み。ルビは独立した文字枠、親文字との関連は次段階とする。[実装前計画](../../../../docs/RapidOCR-New-Recognition-Plan.md)。

dev.235以降、類似語分析はOCR入力専用の巻き戻らない世代を用いる。行の配置・文字送り・読み順・確認状態だけの履歴と、そのUndo／Redoは失効理由としない。文字・追加／削除・行／文字の固定・ページ／セッション変更は失効させる。選択修正は原文を検証して残候補のオフセットを新世代へ更新する。変更履歴だけを分類し、現在性は定数時間で比較する。RapidOCRの処理中編集拒否は別の全編集世代を維持する。[類似語仕様](../../../../docs/Similar-Word-Analysis.md)。

dev.234では、認識用の上下余白を拡大し、認識のための余白と適用する文字範囲を明示的に分離する。元行矩形と実文字画素の矩形を別々に返し、文字送り推定の読み方向を実文字範囲へ制限する。上下には背景判定用の領域を残す。固定ページ画素グリッドで切り出し、同一結果で0.001編集画素以内の丸め差だけなら元状態を保持してUndoを増やさない。空白を行端の文字へ割り当てない一方、枠外で認識した実際の句読点は配置する。

dev.233で選択行再認識を白余白付き画像の1回へ統一した。結果は1候補で、別条件の参考候補は表示しない。自動補完は単一結果の認識スコア・一意な挿入・画像の根拠を使い、従来の複数条件一致は使わない。置換・削除・手修正済み文字の確認は維持する。

dev.232以降は、再認識結果の適用時に同じ行画像から行全体の文字送り・境界・行端を再推定する。文字列が一致した場合も対象。推定設定は通常の画像調整と共有し、固定中の対象は変更しない。文字と幾何を1回のUndo/Redoにまとめ、判定できない画像は文字のみ適用して元の行外形を保持する。追加のPDF描画・全ページ解析は行わない。

現行はPDFテキストレイヤーの復元、NDLOCR-Lite同伴JSON/XMLの座標取込、TXT/TEIの同伴メタデータ検出、手動取込、および画像を用いた文字送り推定に対応する。dev.230で、同梱したRapidOCR日本語モデルによる横書き選択行の再認識・厳格な文字抜け自動補完・原画像と差分の確認採用を追加した。初回操作時だけモデルを読み込み、隔離ワーカー内のモデル・直近ページを再利用する。OCRのためのネットワーク通信は行わない。

`IOcrProvider`による汎用全文OCR基盤、NDLOCR-Liteのアプリ内実行、Google Vision API、外部送信確認、縦書き・ルビ候補生成は未実装である。設計候補のプロバイダー図を実装済みクラス図と混同しない。[選択行再認識の採用仕様](../../../../docs/RapidOCR-Line-Recognition.md)。

## 1. プロバイダー

```text
IOcrProvider
├─ NdlOcrLiteProvider
├─ GoogleVisionOcrProvider
├─ ImportedOcrResultProvider
└─ PdfTextLayerImporter
```

この図は目標契約であり、現行ソースに`IOcrProvider`実装は存在しない。

各プロバイダーは共通のページ、領域、段落、行、単語、文字候補、座標、信頼度、言語、読み順候補へ正規化する。元のベンダーデータは追跡用に保持できる。

## 2. NDLOCR-Lite

- JSON/XML等の構造化結果と生成PDFを複合的に取り込める。
- dev.131では付随ファイル1件256 MiB、候補32件、ページ10,000件、行2,000,000件、行文字列32,768文字を既定上限とし、上限値はサービス構成で差し替えられる。XMLのDTDと外部実体参照は拒否する。形式不正時のフォールバックと資源上限違反を区別し、上限違反は利用者へ失敗として返す。
- 行座標を優先し、ページ画像への変換時のDPI・回転・原点を記録する。
- 外部プロセスとして実行する場合、実行ファイルパス、モデル、進捗、標準出力、キャンセルを管理する。
- 正確な対応形式とCLI引数は採用バージョン固定後に技術検証で確定する。

## 3. Google Vision API

- Page/Block/Paragraph/Word/Symbolを共通モデルへ変換する。
- 独立した行階層が得られない場合は、幾何・改行情報から行を再構築し、推定であることを記録する。
- 認証情報は資格情報ストアまたは安全な外部設定を用い、プロジェクトへ保存しない。
- 送信範囲、料金発生可能性、ネットワーク利用を事前表示する。

## 4. PDFからの復元

OCR付随データがない場合、PDF文字、位置、フォント、描画モードから共通モデルを作る。段落と読み順は推定値とし、信頼度と警告を付与する。不可視判定は理由コードを持つ。

## 5. 行・段落構築

文字方向、角度、近接、ベースライン、重なり、文字サイズを用いてクラスタリングする。縦書きは右から左、横書きは上から下を既定候補とするが、位置から読み順を固定しない。

## 6. ルビ

小さい文字、本文との近接、方向、配置からルビ候補を提示する。自動関連付けは提案扱い。本文文字列、可視ルビ、読み文字列を混同しない。

## 7. 再認識

ページ全体、領域、選択ページを対象にできる。既存編集を上書きせず、差分レビューを経て採用する。実行前に復元点を作る。

## 8. 精度と検証データ

`1/7`、`一/ー`、濁点、旧字体、縦中横、ルビ、斜め見出し、複雑な段組、図表、ノンブルを代表ケースに含める。正解データは著作権と個人情報を確認して管理する。
## 9. 画像を用いた文字幅の自動推定

文字編集モードでは、既知のUnicode文字要素数とページのレンダリング画像を使用し、行または縦列内の文字ごとの送り幅を推定できること。解析時はOCR領域の回転を逆変換し、文字方向に沿ったローカル画像として扱う。

推定処理は、領域外周を優先して推定した背景色との差および画素エッジを文字方向へ投影し、低エネルギー位置を文字境界候補とする。領域全体の最多色だけで背景を決めてはならない。太い見出し文字では文字色の面積が背景より大きくなり、前景と背景が反転するためである。全境界は個別に決めず、既知の文字数、最小・最大文字幅、均等位置からの距離を用いて組合せを最適化する。枠端の非文字領域が全長の6%未満であれば通常の字面余白として外枠を維持し、送り幅の境界だけを補正する。6%以上の明確な空白がある場合は実文字範囲へ始終端も補正する。いずれの場合もOCR文字列自体は変更しない。

最小送り幅は、利用可能な平均送り幅だけでなく、横書きでは行の高さ、縦書きでは列の幅からも算出する。通常の推定では交差軸寸法のおおむね20%を下限候補とし、文字数に対して領域が過密な場合は平均送り幅の65%を上限として実行可能性を維持する。これにより、同じ低エネルギーの隙間へ複数境界が集中し、文字セルが線状になることを防ぐ。文字編集画面の文字セルは選択中のOCR領域だけに表示し、ページ全体へ不要な境界線を常時重ねない。

境界候補の評価では、各セル内で前景と判定された文字画素の被覆率も使用する。OCR文字列上の非空白文字を前景画素のほとんどない区間へ割り当ててはならず、不足率に応じた強いペナルティを与える。空白文字には逆に低被覆率の区間を優先する。最大送り幅も交差軸寸法から制限し、1セルが複数の可視グリフと大きな空白を同時に含むことを抑制する。

最小幅比率、最大幅比率、均等幅への拘束強度、前景画素の必須被覆率はアプリケーション設定として調整可能とする。既定値はそれぞれ20%、165%、35%、12%とし、Portable／インストール双方の設定ファイルへ保存する。設定変更は以後の推定へ適用し、既存の手動編集結果は自動変更しない。

NDLOCRの明示的な縦書き属性は保存済みプロジェクトより新しい根拠として再照合できること。旧版で方向を失ったプロジェクトを開く場合、同一文字列と近接座標により同伴データを対応付け、縦書き属性を復元する。明示属性がない場合のみ、文字数、幅、高さ、および1文字当たりの想定寸法から方向を推定する。横書きとして保存された送り幅を縦書きへそのまま流用せず、縦方向の領域長から再初期化する。

重なり文字、複雑な背景、低コントラスト、枠外へはみ出した文字では判定が曖昧になるため、推定結果に信頼度を付与する。低信頼度でも利用者が結果を確認して修正できるようにし、適用操作は一括してUndo/Redo可能とする。画像差がほとんどない、または文字数に対して領域が小さすぎる場合は、既存の文字幅を変更せず理由を表示する。
