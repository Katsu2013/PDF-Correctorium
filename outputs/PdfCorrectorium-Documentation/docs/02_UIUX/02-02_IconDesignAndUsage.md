## 現行仕様（v1.0.0-dev.274・コミット前確認）

承認済みのMaterial系形状、22pxでの識別性、単純な追加記号と透明な離隔、ファイル比率・しおり比率、回転・見開き・連続スクロールの形状を共有する。同じ操作のメニューとツールバーは共通資源を参照し、単純な画像操作はツールチップ付きアイコンで示す。ダイアログ下部のOK・適用・保存・キャンセル・既定値等にはアイコンを付けない。本文中の旧監査件数は当時の結果である。

dev.263では左右の自動収納タブにも既存のパネル別アイコンを共用する。20pxの正立アイコンと12pxの文字、32pxの短辺を使い、明暗は共通資源を参照する。[寸法・対応表](../../../../docs/AutoHide-Tab-And-Width.md)。

dev.262ではヘッドホン形を読み上げドックの起動に共用する。登録／更新はApply、削除はDeleteを引き継ぐ。適用範囲・固定／自動収納は文字とチェックで示し、新たな複合アイコンを増やさない。ルビ編集の小さな入力欄も既存プロパティの操作と配色を共用する。

dev.261の読み方登録／更新は共有Apply、削除はDelete、右クリックの読み方入力はEditを使う。語やルビを重ねた新しい複合図形は作らない。プロパティの操作ボタンとしてアイコンと文字を併記し、表示設定のチェックボックスと登録一覧には装飾アイコンを追加しない。

dev.252のテーマ切り替えでも、確定済みの図形・バッジ余白・縦横比・回転形状を維持する。通常の前景、補助前景、リンク、差分の色は共通テーマ配色へ追従させ、PDF等の識別色は意味を保つ。22px時と無効状態も両テーマで確認する。

読み上げの再生は三角、停止は四角、一時停止は2本の縦棒を基本形とする。dev.258では利用者指定により、読み上げウィンドウを開くツールバーとメニューは単純なヘッドホン輪郭を共用する。24単位の共有ベクターを使い、小さな再生記号等は重ねない。操作バーのアイコンには操作名・アクセスキー・ツールチップを付け、ダイアログ下部の「閉じる」は文字だけとする。

## 位置付けと文書の状態

本章は、今後の画面追加・修正で使用する共通の設計基準である。メイン／ページ表示／プロパティのツールバー、上部メニュー、右クリック、ダイアログ、実行時生成メニューに適用する。既存部品の見た目と操作意味を維持し、同じ操作のアイコンが画面ごとに異なる状態を防ぐ。

現行の下部ボタン規則（dev.211）: **ダイアログ下部の操作ボタン列にはアイコンを付けない。** OK・適用・既定値に戻す・保存・実行・キャンセル・中止等、操作の名称にかかわらず配置場所を優先する。過去のdev.209／210の適用数は当時の履歴であり、下部配置を現在も追加必須とはしない。

dev.259の読み上げウィンドウは下部ボタン列そのものを持たず、右上の標準×で閉じる。空のフッターを残して余白を予約しない。他のダイアログの上記規則は維持する。

本章の初回基準追記（dev.208）は文書改訂のみだった。dev.209では承認済み形状を再利用する68配置を追加・置き換え、末尾の適用節と版別検証記録へ反映する。全候補を実装済みとはしない。プロジェクト形式・設定形式は変更しない。

## 1. 基本方針

- **MUST：アイコンを表示する同じ操作には同じキー・形状を使う。** ツールバー、メニュー、右クリック、プロパティ、ダイアログ内の操作で意味を変えない。ただしダイアログ下部はアイコンを表示しない。同じ操作でも、下部ボタン列の除外規則が優先する。
- **MUST：採用済み形状を優先して再利用する。** 操作名の文字列や表示言語を見て別々のアイコンを割り当てず、安定した操作IDから参照する。保存先や整列基準などの機能差を見た目の統一に伴って変更しない。
- **SHOULD：新規形状はMaterial Design／Material Symbols系を基本にする。** Outlined系を基本候補とし、既存の輪郭・太さへ合わせる。Materialへ揃えるために確認済みの「開く」やページ回転を作り直さない。
- **MUST：小さくても識別できることを優先する。** 機能のすべてを1個の図柄へ描き込まず、複数ページ・一括・処理対象などの違いは文字ラベルで補う。
- **MUST：単純な操作記号をフォント文字で代用しない。** 新規／変更対象の「←・→・−・＋」等は共有ベクターを使う。数値・ページ番号・入力欄の文字は通常の文字として維持する。既存の文字Tを含むOCRモード表示等は未統一箇所として扱い、文書追記だけで修正済みにしない。
- **MUST：アイコン化で使いやすさを落とさない。** 操作名、ツールチップ、アクセスキー、Tab移動、フォーカス表示、カスタムショートカット表示を維持する。

## 2. 大きさ・輪郭・色

### 設計座標と表示寸法

| 項目 | 基準 |
| --- | --- |
| 形状の設計座標 | 固定24×24。形状だけの外接枠へ切り詰めず、内部余白を含めて描く |
| メニューのアイコン | 現行18 DIPを維持 |
| 小型のページ／しおり等の操作 | 現行18 DIPを維持。既存のサイズ設定を尊重する |
| ツールバー | 現行のサイズ設定に従う。アイコン追加を理由にバーの高さ・縦置き幅を広げない |
| OCR／リンクの整列・サイズ合わせ | 現行24 DIPのアイコン、32×32 DIPのヒット領域 |
| 視認性の基準 | 18・22・24pxのラスタ表示でも判別できるか確認。表示寸法と操作領域は別に扱う |

DIPはWPFの論理寸法であり、実際のピクセル数はDPIで変わる。22pxの画像での判読性確認と、22 DIPの部品サイズ指定を混同しない。縦横比を維持し、拡大表示・高DPIでもストロークや合成記号を切らない。

### 輪郭と色

- 線描画の基本輪郭幅は24×24座標で1.8。端と接続は原則Round。採用済み形状の例外は維持し、Materialから取り込む塗り形状へ機械的に追加のStrokeを付けない。
- 通常は現行の濃いグレー `#263746`、リンクは青 `#2563EB`、PDF文字は赤 `#D32F2F`を使用する。意味のある強調色は1〜3色程度に抑える。
- 色だけで操作・種類・ロック状態・確認状態を区別しない。形状、文字、押下背景、選択表示を併用する。
- 通常／無効／ホバー／押下／キーボードフォーカスで輪郭が判読可能なことを確認する。選択背景・暗い背景・高コントラストで、固定色や透明な余白が判読性を損なわないことを確認する。
- 新しい色・線幅・余白を画面ごとに直書きしない。確認済みの形状を変更する場合は、現行との比較見本で差を示す。

## 3. 合成記号と透明な余白

追加／削除の単純な＋／−の合成は許容する。ただし元の形状と記号が接して見えないよう、記号の周囲を透明に抜く。

| 項目 | 確認済みの設計値（24×24座標） |
| --- | --- |
| ベース輪郭線 | 1.8 |
| ＋／−の線 | 2 |
| 透明に抜く輪郭幅 | 通常8、しおり削除の−だけ9.5 |
| 記号からベースまでの透明幅 | 片側3、しおり削除は3.75 |
| 22pxへ縮小した透明幅の目安 | 片側約2.75px、しおり削除は約3.44px |

白いアウトラインを上から描くだけの方法は使用しない。記号の太い輪郭をベースから減算して透明にし、その上に細い記号を合成する。合成後の塗り形状へStrokeを追加して、透明な離隔を狭めない。

小さな目・ゴミ箱・歯車・鉛筆を別の複雑な図形へ重ねる新規合成は採用しない。検索は虫眼鏡、削除は単独のゴミ箱、編集は単独の鉛筆等を候補とし、詳細はラベルで説明する。確認済みの「開く」の対象バッジ、リンク表示の四隅の枠、既存の子しおり階層表現などは維持対象であり、一般則を理由に勝手に作り直さない。

ページの90度回転と、透明テキスト領域の角度調整・リセットは別操作である。整列アイコンを揃えても、OCRの整列基準とリンクの最初の選択枠基準、ロックの保護範囲を変更しない。

## 5. アイコンを付ける／付けない判断

### 基本の適用表

| 部品・操作 | 基準 | 文字の扱い・注意 |
| --- | --- | --- |
| ツールバーの実行ボタン | **MUST：付ける** | 前／次、増減もベクター。用途を示すツールチップ必須 |
| プロパティの実行操作 | **SHOULD：付ける** | 編集、削除、スポイト、確認、検索、一括処理等。複雑な操作は文字を残す |
| ダイアログの内容領域の実行操作 | **SHOULD：付ける** | 検索、置換、分析、候補作成等。下部ボタン列は除く |
| ダイアログ下部の操作ボタン列 | **MUST：付けない** | OK、適用、既定値に戻す、保存、実行、キャンセル、中止、および同じ列の選択・前後移動等。文字・アクセスキー・Enter／Esc・Tab順を維持 |
| メニュー・右クリックの実行操作 | **SHOULD：付ける** | 同一操作のツールバー／プロパティと同じ形状。項目名は残す |
| 最近開いたファイルの履歴行 | **SHOULD：付ける** | PDF／プロジェクトの対象種別に従い既存形状を再利用。ファイル名・パスは残す |
| アイコンだけで成立する単純操作 | **MAY：アイコン主体** | 前／次、ズーム、整列等。アクセシビリティ名とツールチップを付ける |
| 一括処理、全解除、削除の対象指定 | **MUST：文字を残す** | アイコンは補助。選択対象／ページ内全部／全候補などを文字で区別 |
| OK、通常のキャンセル、閉じる、後で | **原則付けない** | Enter／Escと標準の文字表示を維持。通常のダイアログ終了を指す |
| 内容領域の実行中の検索・分析のキャンセル／中止 | **SHOULD：付ける** | 処理中止は実行操作。文字も残す。ただしダイアログ下部に置かれる場合はアイコンなし |
| 墨消しの色見本 | **付けない** | 色面の判別を優先。色名ツールチップ・選択状態・操作名は維持 |
| メニューの最上位見出し・分類見出し | **原則付けない** | 文字と標準のサブメニュー矢印で分類を示す |
| 通常のCheckBox／RadioButton | **原則付けない** | チェック／ラジオと文章で選択状態を示す。ツールバーの単一／見開きボタンは実行操作として扱う |
| 数値入力、ページ番号、コンボボックスの一般候補 | **原則付けない** | 入力値や候補の文字をアイコンで置換しない |
| 変更前／変更後の比較切替 | **MAY：任意** | 文字と選択状態を優先。追加するなら比較見本を確認 |
| チェック式メニュー・ツールバー表示チェックリスト | **条件付き** | チェック状態を優先。アイコンを追加する場合は別欄等で両立し、見本で確認 |
| 動的メニューの仮項目 | **付けない** | 実際の操作ではないため不足として数えない |

アイコン追加を全コントロールへの機械的な必須条件にしない。原則を外す場合は、操作ID・配置・理由・確認状況を記録する。設計方針からのSHOULD例外は文書群の規定に従ってADRへ残す。

「下部」は内容領域全体の最下部にあるダイアログ共通の操作列を指す。コメント一覧の直下の新規／削除や入力欄の横の検索／置換は対象外。同じ下部列にある操作は種類によらず文字のみとし、位置や動作を変更して除外を回避しない。OS標準のファイル選択・確認ダイアログの外観は上書きしない。

### 表示状態とアクセシビリティ

- アイコンだけのボタンにも意味のある操作名を付ける。画像名やキー名を読み上げ名にしない。
- カスタム可能なショートカットは、固定文字へ戻さず現在の割り当てをツールチップへ反映する。
- アクセスキーはOpen=O、Save=S等の既存の意味ある割り当てを維持する。単にアイコンを追加する変更で、入力欄との競合を新たに作らない。
- チェック、押下、ロック／解除を図柄だけに依存させない。選択状態と操作名も同期する。
- 「戻る」と「リンク先へ」、「選択を削除」と「すべて解除」等、似た形でも対象が異なる場合は文字を残す。識別のために細かい記号を無制限に合成しない。
- 詳しい説明をオフにしても、操作名・ツールチップ・必要な状態・警告・入力エラーは消さない。

### 単純操作の文字省略（dev.246）

文字の一括削除は行わない。画面の文脈と採用済みアイコンだけで判断できる画像の拡大／縮小／全体表示／100%、候補プレビューの前後移動、検索入力横の虫眼鏡はアイコンのみで表示できる。32×32 DIPの操作領域、18 DIPの既存形状、フォーカス・ホバー・無効表示を維持する。倍率値は数値として残す。

操作名はボタンの内部Contentへ残し、日英の翻訳と標準Button Automationから読み取れるようにする。ツールチップに操作名を示し、`KeyboardAccess.Key`で実際のAltキー登録とヒントを維持する。非表示の文字要素でアクセスキーを登録したつもりにしない。共通の`IconOnlyActionButtonStyle`と`ActionIcon.IconOnly`を使用し、通常のアイコン＋文字テンプレートを一律変更しない。採用配置は自動検査へ明示登録する。

dev.246の採用は再OCR4操作、反映候補プレビュー5操作、透明テキスト検索1操作の計10。復帰・分析・一括処理・置換・削除・全解除、リンク先と履歴移動などの対象／意味の区別、行全体／選択文字以降、変更前／後、チェックの文言、メニュー名は残す。ダイアログ下部は本章の文字のみの規則を優先する。ツールバーの「アイコン＋説明」を選んだ利用者の設定は尊重する。[採用・検証記録](../../../../docs/releases/v1.0.0-dev.246.md)。

## 6. 保守・実装上の基準

dev.210では新規単独図柄を `Resources/MaterialActionIcons.xaml` に分離し、既存の `VectorIcons.xaml` から統合する。ActionIcon・ラベルテンプレート・透明離隔を共用し、承認済み形状は変更しない。公式の塗り輪郭は再度Strokeで太らせず、線で定義した専用図柄のみ既存線幅を使う。

- 形状は `Resources/VectorIcons.xaml`、共有描画は `ActionIcon`、単純な合成は `BadgeIconGeometryExtension` を基本とする。新しい画面ごとにPathやフォント記号を複製しない。
- メニュー用とボタン用には独立した表示要素を生成し、共有するのはFreeze可能な形状データと操作定義にする。UI要素そのものを別の親へ共有しない。
- 形状の生成・合成・ファイル読込をマウス移動や再描画のたびに行わない。合成形状は辞書読込時等に生成し、Freezeして再利用する。
- 同じ操作IDから形状・操作名・ツールチップを参照する構成へ段階的に揃える。表示言語のラベル文字列から機能を推測する方式や、配列番号だけへの依存を避ける。
- 例外には理由を残す。既存の手組み描画は一度に置換せず、確認済みの見た目を保持する比較確認を行う。
- 外部形状は必要分だけ取り込み、出典・元リビジョン・ライセンス・変更点を記録する。Material由来の現行形状は[既存の出典記録](../../../../licenses/MaterialSymbols/NOTICE.md)を参照する。文字アイコンフォント全体の同梱を、図柄追加の既定手段にしない。

これは保守の設計基準であり、現行の全操作ID・全画面の描画方式がすでに統一されたという記載ではない。

## 7. 今後の追加・変更手順と受入確認

1. 既存操作と新規操作を区別し、操作IDと配置箇所を決める。上表で「付ける／付けない／条件付き」を判断する。
2. 同じ意味の既存アイコンを探す。既存形状を再利用できる場合は新形状を作らない。
3. 新規候補や確認済み形状の変更は、現行との比較・18／22／24pxの見本を提示する。＋／−の透明な離隔、比率、色、細部を確認してから採用する。
4. 採用結果を本章または個別の採用記録へ記載し、監査・候補一覧では「未承認／承認済み未実装／実装済み／検証済み」を区別する。文書更新だけで実装済みに変更しない。
5. 実装時は、同一操作のツールバー、上部メニュー、右クリック、プロパティ、ダイアログ、動的メニューを一緒に確認する。非表示設定やロック中も表示が崩れないことを確認する。
6. 対象操作の一覧と意図的な除外一覧を検証に使う。既存の診断の対象キーだけを確認して、全アイコンの網羅性が保証されたと扱わない。
7. 100／150／200% DPI、通常／無効／押下／ホバー／フォーカス、明暗背景・高コントラストで確認する。18／22／24pxのラスタ表示では、記号の離隔が潰れず、隣接形状が一体化せず、図柄を判別できることを確認する。
8. アイコン追加による文字の切れ、アクセスキー・Tab順序・ショートカット表示の退行、狭いプロパティや縦置きツールバーの欠落を検査する。

dev.208の基準追記時には上記の新しい網羅検証や高DPI検証は実行していない。dev.209の追加配置に対する実施結果と未検証項目は、同版の検証記録へ記載する。高DPI・全残件の網羅確認を実施済みに読み替えない。
