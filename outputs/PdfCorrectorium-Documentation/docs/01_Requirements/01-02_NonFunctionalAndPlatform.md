# 01-02 非機能・プラットフォーム要求

## NFR-100 データ保全

- 元PDFと既存成果物は、検証合格前に変更しない。
- 保存は同一ボリューム上の一時ファイルと安全な置換を基本とする。
- 重要操作前と形式移行前に保全コピーを作る。
- プロジェクトと元PDFをSHA-256、サイズ、ページ数で照合する。

## NFR-200 性能

- 数百～数千ページを想定し、全ページの描画・OCRオーバーレイ常駐を避ける。
- ページ・サムネイル・OCRモデルは遅延読み込みとキャッシュを用いる。
- UIスレッドでOCR、PDF保存、検証、ハッシュ計算を実行しない。
- 長時間処理は進捗、キャンセル、再試行可能性を表示する。
- 具体的な目標値は代表データセットで基準測定後に確定する（TBD）。

## NFR-300 互換性

- Version 1.0: Windows 11 x86-64、.NET 8。
- ARM64を見据え、ネイティブ依存をインターフェース越しに隔離する。
- PDF機能の対応可否を開く際に検査し、署名、暗号化、破損、権限制限、PDF/A、Tagged PDFの状態を表示する。
- 電子署名を破壊する編集は明確に警告し、原則別名保存とする。

## NFR-400 セキュリティ・プライバシー

- テレメトリは既定で無効。
- クラッシュレポートは明示同意制で、送信内容を確認・編集できる。
- APIキー、認証トークン、文書本文を通常ログへ記録しない。
- Google Vision利用時は外部送信を明示する。
- プラグインは権限宣言、互換性、署名情報、ライセンスを表示する。

## NFR-500 アクセシビリティと国際化

- UI文字列をリソースへ分離し、日本語・英語を提供する。
- キーボードで主要操作を完結できる。
- フォーカス表示、スクリーンリーダー名、十分なコントラスト、色だけに依存しない状態表現を提供する。
- 数値、日付、ショートカット表記はカルチャー差を扱う。

## NFR-600 保守性

- nullable参照型、非同期キャンセル、依存性注入、MVVM境界を用いる。
- PDF演算子、OCRベンダー形式、ストレージ場所をUIへ漏らさない。
- 要求ID、テストID、ADRを相互参照する。
- 依存OSSは正確なバージョンとライセンスをSBOM/第三者通知で管理する。

## NFR-700 可観測性

- Fatal/Error/Warning/Information/Debug/Traceを提供し、既定はInformation。
- 相関ID、プロジェクトID、処理段階を付与する。
- ログローテーション、保管期間、容量上限、診断パッケージを提供する。
