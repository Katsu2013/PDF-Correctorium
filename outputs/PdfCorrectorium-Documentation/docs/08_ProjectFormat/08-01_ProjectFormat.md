# 08-01 `.pdfocrproj`形式

## 形式1.10（dev.200）

`internalLinks[]`に`sourceAreas`（行ごとのクリック範囲）、`sourceAnnotations`（元注釈の参照・矩形・任意の名前）、`unsupportedAction`、`destinationViewType`、`destinationViewParameters`を追加する。複数行のリンクはプロジェクトでは一つの設定として扱い、PDFでは独立した標準Link注釈に展開する。出力の`/NM`識別子で再読込時にまとめる。元注釈は矩形と名前を照合して一意に特定できた場合のみ置換する。

`linkOverlayVisible`は明示的な表示設定、`sourceLinkImportVersion`は既存リンクの読込機能世代を表す。リンク編集モード中の一時的な強制表示は保存設定を上書きしない。危険・未対応アクションは実行せず、一覧で理由を表示する。

新規保存は1.10、最小アプリ版は`1.0.0-dev.200`。形式1.0～1.9を読込可能だが、1.10をdev.199以前で開くことはできない。元プロジェクトまたは保存時バックアップを保管する。以下は各旧形式の履歴である。

## 形式1.9（dev.199）

`textDecorations[]`に任意の`evenPagePosition`を追加する。指定がない既存プロジェクトは偶数ページも従来の`position`に従う。指定があれば出力後の物理ページ番号の偶奇で配置を切り替える。表紙を除外する場合は従来の`firstPage=2`、`pageNumberOffset=-1`を使い、最初のページには文字を置かず、2ページ目に「1」を印字する。`{total}`は対象範囲の終端に番号補正を加えた値を示す。新規保存は1.9、最小アプリ版は`1.0.0-dev.199`。形式1.0～1.8を読込可能で、旧版で新規保存した1.9は開けない。

## 形式1.8（dev.198）

形式1.8は元PDFから取り込んだリンクの識別情報（`sourceAnnotationReference`、`originalSourceBounds`、`isModified`）と、既存リンクの読込完了状態（`sourceLinksInitialized`）を記録する。既存リンクを変更・削除したときは、元の注釈を出力時に置換・除去し、二重化を避ける。プロジェクトにはページ番号・ヘッダー／フッター・文字透かしの設定を`textDecorations[]`として保存する。各設定は種類、文字列（`{page}`、`{total}`を使用可）、対象ページ範囲、番号オフセット、位置、余白、文字サイズ、色、不透明度、有効状態を持つ。画像透かしは対象外。新規保存は1.8、最小アプリ版は`1.0.0-dev.198`であり、形式1.0～1.7は読み込む。

## dev.176の旧形式読込と元PDF再選択

形式1.5と1.6も形式1.4以降と同じく、元PDF参照の正本は`project.json`である。重複する`source/source-reference.json`が存在しないことを読込エラーとして扱わない。保存方式、相対参照パス、論理ページ列は当該形式の規則で検証する。

通常モードで参照先PDFが見つからない、サイズが変わった、またはSHA-256が一致しない場合、理由と元PDF名を表示して再選択を提案する。選択したPDFは保存済みのサイズとSHA-256が一致するときだけ読み込む。新しい相対パスはメモリ上へ設定して未保存状態とし、利用者がプロジェクトを保存したときに確定する。異なるPDFへの編集情報の流用はしない。内包PDFの欠落・破損は外部PDF再選択で迂回しない。

## 形式1.7（dev.172）

形式1.7は`internalLinks[]`へ任意の`externalUri`を追加する。値がある場合はHTTP/HTTPSの絶対URLだけを許可し、文書内の移動先ページは不要である。値がない場合は従来どおり固定ページIDによる文書内リンクとして扱う。新規保存は1.7、最小アプリ版は`1.0.0-dev.172`である。形式1.0～1.6は読み込む。

## 形式1.6（dev.163）

形式1.6は`redactions[]`へ`shapeKind`と`pathPoints[]`を追加する。`pathPoints`はPDF左下原点の閉じた輪郭で、空配列は従来の`bounds`矩形を表す。非矩形は3～4,096点、全座標は有限かつページ内で、計算した外接矩形が`bounds`と一致しなければ読込を拒否する。最小アプリ版は`1.0.0-dev.163`である。

## 1. 概要

`.pdfocrproj`はZIP互換の独自拡張子である。ポータブルモードではPDFを含む単一ファイルとして扱い、通常モードでは通常の元PDFを現在位置のまま参照する。埋め込みPDFからの変換または外部ページ挿入で作成した管理対象PDFの永続化が必要な場合だけ、隣接する`.assets`フォルダーと組にして扱う。ページ削除・並べ替え・回転は論理ページ列として保持し、PDF全体を複製しない。

## 2. 構成

形式1.9が新規保存する構成は次のとおり。`project.json`をプロジェクト情報、OCRページ情報、墨消し指定、文字装飾設定の正本とし、旧形式で重複していた`source/source-reference.json`、`ocr/pages/page-*.json`、再生成可能なサムネイルは保存しない。旧形式の各エントリは互換読込する。

```text
project.pdfocrproj
├─ manifest.json
├─ project.json
└─ source/document.pdf              # ポータブルモードのみ・無圧縮格納
```

`ocr/imported`、`edits`、`review`、`history`、`validation`、`settings`、`attachments`の分離エントリは目標設計であり、現行形式には作成されない。レビュー状態、しおり、表示設定、コメント、タグ、内部リンク、墨消し範囲等の実装済み情報は`project.json`へ含める。監査履歴、検証レポート、UI作業状態は未実装である。

校正・確認モードで更新した領域のレビュー状態も保存対象となる。一方、校正の選択モードと状態フィルターは一時UI状態であり、`project.json`には保存しない。


dev.133の形式1.2は保存方式、コメント、タグ、内部リンクを追加し、dev.137の形式1.3はプロジェクト配下に限定されない正規化済み相対参照を追加した。dev.143の形式1.4は論理ページ列を追加し、重複エントリを廃止する。dev.152の形式1.5は矩形墨消し指定、dev.163の形式1.6は輪郭と入力種別、dev.172の形式1.7はWebリンク先、dev.198の形式1.8は既存リンクの編集識別情報と文字装飾設定、dev.199の形式1.9は偶数ページの別位置を追加する。1.0～1.8は互換読込し、次回保存時に1.9へ更新する。**新しく保存した1.9はdev.198以前で開けない**ため、旧版利用が必要な場合は元プロジェクトまたは保存時バックアップを保管する。一般的な移行・ロールバックUIは未実装である。

## 4. 元PDF

別名保存時に`Embedded`（ポータブルモード）または`Relative`（通常モード）を明示的に選択する。新規PDFの初期値はポータブル動作で`Embedded`、インストール動作で`Relative`とし、上書き保存では現在の方式を維持する。ポータブルモードは元PDFを`source/document.pdf`へ無圧縮格納し、相対パスを持たない。通常モードで通常の外部PDFを保存する場合はPDFをコピーせず、`project.json`の`sourcePdf`へプロジェクトディレクトリから元PDFへの相対パス、SHA-256、サイズ、物理ページ数を記録する。別名保存では新しい保存先を基準に相対パスを再計算する。

元PDFがプロジェクトへ埋め込まれている場合、または外部ページ挿入後のPDFが一時作業領域にある場合は、そのまま外部参照すると消失するため、`<project-name>.assets/<SHA-256>.pdf`へ書き出して参照する。通常の外部PDF、および削除・並べ替え・回転だけを行ったPDFでは`.assets`を作成しない。通常モードの保存成功後、現行・自動保存・世代バックアップ・復旧直前コピーのどれからも参照されない64桁ハッシュ名PDFだけを削除し、空フォルダーも整理する。任意名ファイルや別プロジェクトの参照候補は削除しない。別ドライブ間では相対パスを表現できないため、自動コピーせず保存を中止し、ポータブルモードまたは同一ドライブへの保存を案内する。

形式1.3以降では絶対パスヒント、ルート付きパス、ドライブ指定、空要素、`.`を禁止し、親フォルダーを表す`..`だけを許可する。形式1.2の相対参照は従来どおりプロジェクト配下に限定する。ハッシュまたはサイズ不一致は読込エラーとし、別ファイルへの誤適用を防ぐ。旧形式の参照は読込時に正規化する。

`pageSequence`は表示順に`pageId`、元PDF内の`sourcePageNumber`、0／90／180／270度の`rotationDegrees`を持つ。OCRページ、しおり、コメント、タグ、内部リンクは固定IDに追従する。削除は列から除外、並べ替えは列順変更、回転は角度更新とOCR座標変換で表し、元PDFを変更しない。外部ページ挿入時だけ現在列と挿入PDFを一度結合し、新しい物理元PDFと同一順の列へ正規化する。最終出力時も同様に一度だけ実体化する。

`redactions`は固定`id`、対象`pageId`、PDFポイントの`bounds`、`shapeKind`、任意の`pathPoints`、`colorHex`、任意の`sourceRegionId`／文字範囲と作成時刻を持つ。保存時は件数上限、ID重複、対象ページ、有限・正面積かつページ内の外接矩形、輪郭点数・座標・外接矩形一致、`#RRGGBB`色、文字範囲を検証する。元OCR領域参照が失われても保存輪郭を正本として保持し、警告扱いとする。プレビュー画像や墨消し後ページ画像はプロジェクトへ保存せず、PDF出力時に生成する。

## 5. 編集中の作業領域

```text
Portable: <app>/workspaces/page-edits/<session-id>/
Installed: %LocalAppData%/PdfCorrectorium/Workspaces/page-edits/<session-id>/
```

外部ページ挿入で必要な一時PDFは、プロセスIDと乱数を含むセッションIDの専用ディレクトリへ置き、ロックファイルを開いて稼働中セッションを識別する。削除・並べ替え・回転の履歴は論理モデルだけを保持し、サムネイル画像や作業PDFをスナップショットへ含めない。挿入履歴から到達不能になったPDFは直ちに削除し、終了時はセッション全体を削除する。異常終了で残ったロック取得可能なセッションは、次回セッション作成時に回収する。プロジェクト全体の最終チェックポイントと起動時の自動復旧候補提示は未実装である。保存済みプロジェクトの自動保存・バックアップ復元に加え、未保存プロジェクトは`<WorkspaceDirectory>/recovery/<project-id>.autosave.pdfocrproj`へ元PDFを内包して保存し、該当ファイルを明示的に開いて復旧する。

## 6. 安全保存

作業領域を整合性検査 → 新しいZIPを一時生成 → ZIP/JSON/必須参照検証 → 世代バックアップ → 原子的置換、の順とする。元ファイルへ直接追記しない。

dev.123で空文字編集の保持と、画面から戻す際の親領域・補正方式・出力属性欠落を修正した。dev.130では、エントリ件数、総展開容量、圧縮率、JSON、サムネイル、内包PDFに設定可能な既定上限を設けた。dev.131では圧縮済みファイル自体の容量をZIP解析前に検査し、危険なエントリ名も拒否する。dev.143では内包PDFの展開キャッシュをアクセス順で最大16件・合計4 GiBに制限し、現在要求中のPDFは保持する。再利用前にはSHA-256を再計算し、展開用一時名は並行処理で衝突しない。ただしZIP検証の成功だけで全属性・全入力の無損失を保証するものではない。常設した保存・PDF出力試験の範囲は[テスト戦略](../11_Test/11-01_TestStrategy.md)を参照する。

## 7. バックアップ

- 通常保存: 検証済み新規ZIPへ置換する前に世代バックアップを1件作成
- 世代保存: 既定5世代かつ合計4 GiB（最新1件は容量超過でも保持）
- 旧固定名`.bak`: 読込互換だけ維持し、新規作成しない。次の正常保存後に整理する
- 復旧直前コピー: 最新1件
- 重要操作前: スナップショット
- 形式移行前: 保全コピー必須

画面設定で変更できるのは世代数であり、容量上限は現行実装の保守的な固定値である。

## 8. 診断・修復

現行実装はZIP・必須JSON・プロジェクトID・元PDF参照・論理ページ列・ページ番号重複・読込資源上限の検証、および自動保存／旧固定名バックアップ／世代バックアップからの復元を提供する。以下の分類型修復UI、旧ページJSONからの救出、読み取り専用・救出モードは未実装である。

| 区分 | 例 | 動作 |
|---|---|---|
| 自動修復 | キャッシュ、サムネイル、索引欠落 | 再生成 |
| 確認後修復 | 不完全なUndo、壊れたUI配置 | 除去・再構築 |
| 復旧候補 | ページJSON破損 | 自動保存/スナップショットから復元 |
| 修復困難 | 元PDFとページ構成不一致 | 読取専用・救出 |

通常、読み取り専用、復旧、データ救出の各モードを持つ。修復は元を直接変更せず、新規プロジェクトを生成して再検証する。

## 9. 互換性

- 旧`PdfOcrEditorProject`形式識別子と形式1.0/1.1/1.2/1.3/1.4を互換読込し、次回保存時に現行1.5へ更新する。未対応形式は検証・読込の双方で拒否する。一般的な明示移行器は未実装である。
- 新形式を古いアプリで開く場合は読み取り専用または拒否し、理由を表示する。
- 移行は冪等性、データ保持、ロールバックをテストする。
- JSON Schemaは未同梱であり、各formatVersionごとの公開が必要である。
