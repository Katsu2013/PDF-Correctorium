# 08-01 `.pdfocrproj`形式

## 1. 概要

`.pdfocrproj`はZIP互換の独自拡張子である。通常は単一ファイルとして扱い、編集中は作業ディレクトリへ展開する。

## 2. 構成

dev.132が実際に読み書きする構成は次のとおり。ページJSONは`project.json`と同じページモデルの複製であり、サムネイルは再生成可能な任意キャッシュである。

```text
project.pdfocrproj
├─ manifest.json
├─ project.json
├─ source/source-reference.json
├─ source/document.pdf              # 内包時のみ
├─ ocr/pages/page-000001.json
└─ thumbnails/page-000001.jpg        # 任意
```

`ocr/imported`、`edits`、`review`、`history`、`validation`、`settings`、`attachments`の分離エントリは目標設計であり、現行形式には作成されない。レビュー状態、しおり、表示設定等の実装済み情報は`project.json`へ含める。コメント、タグ、監査履歴、検証レポート、UI作業状態は未実装である。

校正・確認モードで更新した領域のレビュー状態も保存対象となる。一方、校正の選択モードと状態フィルターは一時UI状態であり、`project.json`には保存しない。

## 3. manifest

```json
{
  "format": "PdfCorrectoriumProject",
  "formatVersion": "1.1",
  "minimumApplicationVersion": "1.0.0-dev.123",
  "applicationVersion": "1.0.0-dev.132",
  "projectId": "uuid",
  "createdAtUtc": "2026-07-20T00:00:00Z",
  "lastSavedAtUtc": "2026-07-20T00:00:00Z"
}
```

dev.123から保存形式を1.1とし、保存アプリ版はビルドの情報から取得する。dev.132でアプリ版を進めても形式1.1と最小対応アプリ版dev.123は変えない。`HasEditedText`を導入し、意図的な空文字を未編集と区別する。1.0は互換読込し、次回保存時に1.1へ更新する。**新しく保存した1.1はdev.122以前で開けない**ため、旧版利用が必要な場合は元プロジェクトまたは保存時バックアップを保管する。一般的な移行・ロールバックUIは未実装である。

## 4. 元PDF

標準は外部参照、任意で内包。参照情報は相対パス、絶対パスヒント、SHA-256、サイズ、ページ数を持つ。探索順は相対パス、前回パス、同一フォルダー、利用者再指定。ハッシュ不一致時は自動適用しない。

## 5. 編集中の作業領域

```text
Portable: <app>/workspaces/page-edits/<session-id>/
Installed: %LocalAppData%/PdfCorrectorium/Workspaces/page-edits/<session-id>/
```

dev.130のページ編集用PDFは、プロセスIDと乱数を含むセッションIDの専用ディレクトリへ置き、ロックファイルを開いて稼働中セッションを識別する。現在状態または到達可能なUndo/Redo履歴から参照されなくなったPDFを削除し、終了時はセッション全体を削除する。異常終了で残ったロック取得可能なセッションは、次回セッション作成時に回収する。プロジェクト全体の最終チェックポイントと起動時の自動復旧候補提示は未実装である。保存済みプロジェクトの自動保存・バックアップ復元に加え、未保存プロジェクトは`<WorkspaceDirectory>/recovery/<project-id>.autosave.pdfocrproj`へ元PDFを内包して保存し、該当ファイルを明示的に開いて復旧する。

## 6. 安全保存

作業領域を整合性検査 → 新しいZIPを一時生成 → ZIP/JSON/必須参照検証 → 世代バックアップ → 原子的置換、の順とする。元ファイルへ直接追記しない。

dev.123で空文字編集の保持と、画面から戻す際の親領域・補正方式・出力属性欠落を修正した。dev.130では、エントリ件数、総展開容量、圧縮率、JSON、サムネイル、内包PDFに設定可能な既定上限を設けた。dev.131では圧縮済みファイル自体の容量をZIP解析前に検査し、ドライブ指定、絶対パス、空要素、`.`、`..`を含むエントリ名も拒否する。内包PDFのキャッシュ再利用前にはSHA-256を再計算し、展開用一時名は並行処理で衝突しない。ただしZIP検証の成功だけで全属性・全入力の無損失を保証するものではない。常設した保存・PDF出力試験の範囲は[テスト戦略](../11_Test/11-01_TestStrategy.md)を参照する。

## 7. バックアップ

- 通常保存: 直前バックアップ
- 世代保存: 既定5世代
- 重要操作前: スナップショット
- 形式移行前: 保全コピー必須

保管数と容量上限は設定可能にする。

## 8. 診断・修復

現行実装はZIP・必須JSON・プロジェクトID・元PDF参照・ページ番号重複・読込資源上限の検証、および自動保存／直前バックアップ／世代バックアップからの復元を提供する。以下の分類型修復UI、ページJSONからの救出、読み取り専用・救出モードは未実装である。

| 区分 | 例 | 動作 |
|---|---|---|
| 自動修復 | キャッシュ、サムネイル、索引欠落 | 再生成 |
| 確認後修復 | 不完全なUndo、壊れたUI配置 | 除去・再構築 |
| 復旧候補 | ページJSON破損 | 自動保存/スナップショットから復元 |
| 修復困難 | 元PDFとページ構成不一致 | 読取専用・救出 |

通常、読み取り専用、復旧、データ救出の各モードを持つ。修復は元を直接変更せず、新規プロジェクトを生成して再検証する。

## 9. 互換性

- 旧`PdfOcrEditorProject`形式識別子と形式1.0/1.1を互換読込し、未対応形式は検証・読込の双方で拒否する。一般的な明示移行器は未実装である。
- 新形式を古いアプリで開く場合は読み取り専用または拒否し、理由を表示する。
- 移行は冪等性、データ保持、ロールバックをテストする。
- JSON Schemaは未同梱であり、各formatVersionごとの公開が必要である。
