# 00-02 設計思想

## 中心原則

1. **PDF編集を主役にする。** プロジェクト管理は編集を支える裏方とする。
2. **元データを壊さない。** 編集中はOCR編集レイヤーに変更を保持し、元PDFを直接変更しない。
3. **失敗しても戻れる。** Undo/Redo、自動保存、スナップショット、世代バックアップ、診断、修復を中核機能とする。
4. **日本語書籍を例外扱いしない。** 縦書き、右開き、縦中横、ルビ、縦横混在、回転をデータモデルの基本概念にする。
5. **大量処理の疲労を減らす。** 頻出操作は少ないクリック数とキーボード操作で完了させる。
6. **意味と幾何を分離する。** 認識文字列、読み順、文字方向、物理回転、位置、伸縮を独立して編集できるようにする。
7. **安全性を利便性より下げない。** 保存後検証は無効化不可とし、重大な検証失敗時は成果物を確定しない。
8. **高度さを段階的に見せる。** 一般利用者向け基本ワークスペースと専門家向け詳細パネルを両立する。
9. **交換可能な境界を作る。** PDFレンダラー、OCRプロバイダー、永続化、プラットフォーム依存コードを抽象化する。
10. **プライバシーを既定にする。** テレメトリは既定で無効。外部OCR送信は明示し、機密情報をログへ出さない。
11. **長く読めるデータを残す。** プロジェクト形式はバージョン付き、人間可読なJSON中心、移行可能とする。
12. **設計判断を記録する。** 重要な変更はADRに残し、決定理由と代替案を追跡可能にする。

## UXの最重要目標

> 大量ページのOCR修正を、少ない操作で、判断の流れを中断せず、安心して続けられること。

## 判断の優先順位

データ保全 → 出力の正しさ → 作業効率 → 相互運用性 → 見た目の洗練、の順に優先する。ただしアクセシビリティを後回しにする意味ではない。
