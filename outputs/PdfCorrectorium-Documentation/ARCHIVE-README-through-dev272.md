# PDF Correctorium 開発ドキュメント


## 現行設計の基準（dev.271・ソース準備／再ビルド未実施）

文書処理は完全ローカルで、利用者が依頼するWebリンク・更新確認は許可する。従来の安全上限と墨消し保護を維持する。配布全件の記録・照合、利用者データを消さずに除外する公開用ステージ、完成ZIPの照合を追加し、診断7プロジェクトとCIを揃える。実ビルド、配布認証、署名・外部公開の完了とは区別する。詳細は docs/Local-Processing-And-Redaction-Scope.md と docs/releases/v1.0.0-dev.271.md。

## 前回設計の基準（dev.270）

手動でまとめたChapterと1が、ページ表示後の読み上げで分かれる問題を修正。編集履歴用に残した削除済みOCR項目を、有効な読み順へ戻さない。段落編集・保存・読み上げで有効項目の順を揃え、既存の段落IDを維持する。削除済み文字は読まず、墨消し・読み上げ対象外等の保護処理は維持する。詳細は docs/releases/v1.0.0-dev.270.md。

## 前回設計の基準（dev.269・2026-10-29）

読み上げは原文の検索・コピーを維持する方式を採用する。外部リーダーのドットの発音や短い間は許容し、登録読みへの完全一致は保証しない。Altと言語情報の保存を継続し、出力完了では「保存した読み方情報」と外部リーダーでの発音差を案内する。本文置換・読み方のActualText指定・新しい解析／保存工程は追加しない。アプリ内読み上げは登録辞書を使用する。詳細は docs/Pdf-Reading-Interoperability.md と docs/releases/v1.0.0-dev.269.md。

## 前回設計の基準（dev.268・2026-10-29）

読み方付きPDFが改行ハイフンで出力停止する問題を修正。PDFiumのU+0002と元のハイフンだけを同一として照合し、文字の削除・置換や読み方の省略は行わない。提供された450ページのプロジェクトで269ページを含む532行の読み方保存を検証。詳細は docs/releases/v1.0.0-dev.268.md。

## 前回設計の基準（dev.267・2026-10-29）

読み方は本文と分離したPDFのAlt情報として保存し、確認用ルビは画面にだけ表示する。共通辞書と行例外の優先順位、文字・位置を維持する。MCIDとParentTreeで文字へ関連付け、実ファイルから再読込して検証する。墨消し情報を持ち越さず、無変更リンク等の重複処理を省く。対応リーダーでの実音声確認は別に行い、すべてのリーダーで有効とは主張しない。詳細はリポジトリの docs/Pdf-Reading-Export.md と docs/releases/v1.0.0-dev.267.md。


## 前回設計の基準（dev.266・2026-10-29）

dev.266ではChapter／縦書きの1を手動で同じ段落にでき、編集・外枠・読み上げへ共通に反映する。パネル収納は左右別に一括、固定は個別とし、後から開くパネルも収納状態へ従う。[仕様](../../docs/Chapter-Grouping-And-Side-AutoHide.md)、[検証・配布](../../docs/releases/v1.0.0-dev.266.md)。

dev.264では、段落編集で各段落の外枠を薄く表示し、選択中だけ強調する。既存の枠表示・不透明度へ連動し、現在ページだけをキャッシュして描画する。「まとめる」の制限変更は別途回答待ち。[仕様](../../docs/Paragraph-Outlines.md)、[検証・配布](../../docs/releases/v1.0.0-dev.264.md)。

dev.263は自動収納タブを共通アイコン＋文字の32px幅とし、標準ピンとメニューの両方で収納前の幅を引き継ぐ。旧0／100px幅を補正し、有効な展開幅を復元する。[追加設計](../../docs/AutoHide-Tab-And-Width.md)、[検証・配布](../../docs/releases/v1.0.0-dev.263.md)。以下はdev.262で追加した機能と互換性の記録。

dev.262で追加した共通の読み方辞書と行ごとの例外、ルビのダブルクリック編集、読み上げのドッキング、左右端への自動収納と復元を維持する。保存は形式1.14／最小読込dev.262、旧1.0～1.13は読める。設定21と既存PDF/OCR資源は維持する。[採用設計](../../docs/Shared-Readings-And-Docked-Speech.md)、[当時の検証・配布](../../docs/releases/v1.0.0-dev.262.md)。

## 要求の表記

- `MUST`: Version 1.0で必須。
- `SHOULD`: 原則実装。技術上の理由で外す場合はADRが必要。
- `MAY`: 任意または将来拡張。
- `TBD`: 利用者確認または技術検証が必要。
