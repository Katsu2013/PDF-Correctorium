# 共通OCR補正辞書 — 実装計画

2026-10-25。利用者承認済みの計画を`1.0.0-dev.243`で実装する。正本の辞書追加に伴い、新規保存形式は1.12、最低読込版dev.243、設定形式21。検証結果は[dev.243](releases/v1.0.0-dev.243.md)へ記録する。以下は当初の計画と安全条件を残した設計仕様であり、測定値や未実装の後段項目を実装済みと読み替えない。

最終配布は[dev.244](releases/v1.0.0-dev.244.md)。未集計の語句／ルール頻度は0件と捏造せず空欄にする。実装試験・合成データの計測値と、実450ページの起動・CPU／メモリ等の未測定範囲を同リリース記録で区別する。

## dev.243の実装対応

- `OcrLexicon`（正解語・無視語・安定IDを持つルール）を`project.json`へ追加。2,000件／区分、2～64 Unicodeテキスト要素、1文字全域置換・空白・制御文字・重複IDを拒否する。規則の照合範囲は英数字が完全トークン、日本語は明示登録した完全語句で自動判定する。自動適用のチェックはルールごとに保持する。
- `OcrLexiconIndex`、`OcrWordAccumulator`、既存分析器の`PreparedIndex`で共通化。英数字の削除シグネチャ、OCR混同、重み付き距離を再利用し、日本語の登録語句も文字要素の削除シグネチャで絞る。
- `MainWindowViewModel.OcrLexicon.cs`は単一の低優先度ジョブを管理する。700msの初期遅延、600msの操作停止を目安に、前景処理中は250ms単位で待つ。入力・操作をブロックする既存の処理状態は使わない。対象ページの集計済み寄与を差し替え、途中状態の寄与を引かない。保存時に未完了の集計を待たない。
- 通常候補は表示中に勝手に並べ替えない。部分修正時の再ベースを維持し、同じ現在世代の候補を画面の再オープンでも再利用する。「分析」は明示的な再構築。文字／辞書変更後は一覧を保持しつつ再分析を求める。
- 再OCRの確認画面に辞書候補を併記し、最終文字で既存画像から調整する。自動ルールの許可とモデルの信頼度は別物として扱う。原文→生OCRに未確認の置換・削除が残る場合は、辞書ルールが許可済みでも確認画面へ進む。
- 日本語の自動単語抽出、複数資料への辞書共有、学習画像保存、モデル学習は後段のまま。

## 1. 目的と初期範囲

- 現行の類似語検索・頻度集計・登録語／無視語を共通化し、普段の単語修正と選択行の再OCRで同じ資料用辞書を使う。
- 正解語・誤認識からの補正ルール・無視語をプロジェクトに保存する。頻出するだけの語を確認済みの正解に昇格させない。
- 再OCRの辞書候補は、認識した語と候補のUnicodeテキスト要素数が同じものに限定する。既存OCRとの文字数一致ではない。既存の文字抜け補完と、通常の単語修正の文字数が変わる候補は別機能として維持する。
- 一度集計した文字列を索引化し、再認識のたびに全文書を読み直さない。初期表示・編集・ページ描画・利用者が開始したOCRを優先する。
- 初期は資料限定。アプリ共通への自動蓄積、外部送信、モデル再学習、OCRモデルの文字辞書の書き換えは行わない。
- 初期は英数字に加え、明示登録した日本語語句も対象にする。日本語の自動的な単語抽出は後段とする（利用者回答で確定）。
- 明示登録ルールの自動適用も初回実装に含める。自動適用は利用者が許可した同文字数の完全一致ルールだけとし、登録語・頻度・近似一致だけでは自動適用しない（利用者回答で確定）。

## 2. 利用者の操作

### 普段の単語修正

既存の「類似語・誤認識候補」画面を残す。保存された正解語・無視語を初期表示し、集計済み索引から候補を作る。「再分析」は必要時の明示的な全体更新として残す。再分析しなければ何も使えない構造にはしない。

- 修正の確認時に「この語を資料の正解語に登録」「この誤り→正解を登録」を必要時に選べる。初期は未選択。文章全体の手修正から補正ペアを勝手に推測・登録しない。
- 修正と同時に選んだ登録は1回のUndoで一緒に取り消す。辞書だけの追加／削除／有効変更も独立したUndo対象とする。
- 登録語・補正ペア・無視語を同じ辞書管理画面で編集できる。頻度表は参考情報として分け、確認済みの正解と混同しない。
- 一覧の並べ替え、選択、赤い差分、候補への移動、固定中の修正禁止を維持する。背景更新だけで一覧を消したり、選択中の行を別候補へ差し替えたりしない。
- 純粋な再集計で候補が増減した場合は更新を知らせ、利用者の操作で一覧を更新する。自分が適用した候補だけを除く現在の挙動は維持する。

### 再OCR

dev.242の原画像・入力欄・差分プレビュー・「認識結果に戻す」を基礎にする。

1. RapidOCRの生の結果を保持したまま共通索引へ問い合わせる。
2. 候補があれば「認識語→補正候補」と、確認済みルール／登録語／文書頻度という根拠を示す。自動許可がないものや複数候補は利用者が選び、入力欄へ反映する。自動許可済みで安全条件を満たす明示ルールは自動適用へ進める。新しい大きな説明エリアや、同じ文章を並べた重複表示は増やさない。
3. 「認識結果に戻す」は、辞書補正前の生のRapidOCR結果へ戻す。
4. 適用する最終文字列が決まってから、既に得た画像で文字幅を調整し、文字と配置を1回のUndoへまとめる。辞書候補の検索でPDFを再描画・再OCRしない。

辞書候補がない場合は従来の一致／高信頼の文字抜け補完の経路を維持する。自動許可のない置換候補がある場合は、文字抜け補完の自動適用に混ぜず確認へ回す。**生の結果が既存文字と一致したときの早期終了より前に辞書を照会する**。これにより、既存OCRとRapidOCRが同じ誤りを出した場合にも辞書候補を提示できる。

新しい操作にも既存のアイコン・キー操作・説明表示規約を適用する。ダイアログ下部の確定／取消ボタンは文字だけにする。

## 3. 保存する情報と再生成する情報

| 情報 | 保存先の設計案 | 性質 |
| --- | --- | --- |
| 正解語・補正ルール・無視語 | `project.json`の新しい`ocrLexicon` | 利用者の正本。安定ID・有効状態・語／補正元／補正先・照合範囲を持つ |
| 語ごとの出現件数・集計対象の識別情報 | ZIP内の任意エントリ`cache/ocr-word-counts.json` | 検証できた集計のみ通常保存時に同梱。なくても開け、再生成できる |
| 語長別・混同文字別の検索索引、領域別の寄与 | メモリ内 | 現在の文書だけを上限付きで保持。全OCR本文や位置一覧をプロジェクト内へ二重保存しない |

辞書に必要なのは文字情報であり、行画像・学習データセットは保存しない。辞書は校正作業データであり、墨消し済み成果物ではない。PDF出力には埋め込まず、他の資料の辞書へ勝手にコピーしない。

保存は既存の一時ZIP作成→検証→バックアップ→置き換えを利用する。プロジェクト保存時点の本文・辞書と一致する完成済み集計だけを保存し、集計待ちで保存を止めない。途中の集計や世代が合わない集計は省略する。

新しい正本の保存項目にはデータ互換性の設計が必要。旧形式は辞書なしとして読めるようにする。新形式番号は1.12を候補とするが、最低読込版は実際に対応を実装・検証したアプリ版から決める。古いアプリで保存して辞書だけ消失することを避ける。アプリのリビジョンが上がるだけで保存形式を上げることはしない。

## 5. 候補の判定

### 優先順位

適用不可・固定・無視／補正禁止を先に除外し、その後に次を比較する。

1. 利用者が明示登録した、適用範囲の一致する「誤→正」ペア。
2. 利用者が確認した正解語。
3. 文書内の頻度と、現行のOCR混同・距離による候補。

出現回数や確認回数が増えただけで自動適用の許可へ昇格させない。`mode`と`node`のように両方正しい語は、同文字数・高頻度でも確定できない。複数候補、数値・版番号・識別子などは保守的に扱う。

### 同文字数の意味と位置

- 「文字数」はUTF-16長ではなくUnicodeテキスト要素数。文字列内の参照位置は現行と同じUTF-16オフセットで保持し、両者を混同しない。
- 再OCR用は語長別の索引で同文字数へ絞る。通常の単語分析は現行の挿入・削除等も残し、「同文字数のみ」の絞り込みを追加できる設計にする。
- 大文字小文字、全角半角、句読点を勝手に正規化しない。検索用の混同キーと原文を分け、適用直前に原文一致を検証する。
- 同文字数でも字幅が同じとは限らない。通常の単語修正は既存の文字枠保持を基本とし、再OCRでは最終候補に対して現行の画像調整を使う。
- 同文字数でもUTF-16長が変わることがある。複数置換は後ろから適用し、残候補のオフセット更新を省略しない。

### 日本語の初期対応（利用者回答で確定）

英数字は現行の単語抽出を流用する。日本語は明示登録した語句・補正ペアの照合から始め、文書全体の自動分かち書きは追加しない。登録語句の近似照合は既知の語長・候補数を制限し、意味の正誤判定をしたとは扱わない。

日本語は単語境界が曖昧で、登録語句の出現数と文書全体の単語頻度は同じではない。両者を別の根拠として表示する。自動適用する場合も登録した補正元語句全体の完全一致に限り、推定した単語境界や近似一致を根拠にしない。日本語の未登録の任意部分文字列や1文字の全域置換は、自動適用へ含めない。英数字は単語全体の一致とし、単語内の一部だけを勝手に置換しない。

### 明示ルールの自動適用（初回実装に含める・利用者回答で確定）

自動適用の許可はルールごとに既定オフ。利用者が明示的に許可した同文字数・補正元全体の完全一致ルールだけを対象とし、対象一致・候補一意・非固定・現在世代を適用直前に確認する。英数字は単語全体、日本語は登録した語句全体を照合する。頻度・正解語への近似一致だけの候補は自動適用しない。競合・重複・循環するルールは自動適用を拒否する。置換結果へ別のルールを連鎖させず、生の結果に対し1回だけ評価する。

自動適用の実行箇所は、利用者が開始した再OCRの適用経路とする。背景の辞書集計、プロジェクトを開く操作、単語一覧の表示だけで本文を勝手に変更しない。通常の単語修正は既存の選択・確認による適用を維持する。

RapidOCRのスコアを辞書補正後の文字の認識信頼度として流用しない。既存の画像根拠付き自動脱字補完とは許可理由を分離し、辞書で置換した文字をモデルが読めたことにしない。補正前の結果と規則を保持し、文字・配置をまとめてUndoできるようにする。

## 6. バックグラウンド処理

### 読込と優先順位

1. 正本の辞書を復元する。現在文書と一致する頻度キャッシュがあれば再利用する。
2. 初期ページの表示後、保存済みOCR文字列から背景集計を始める。語の検索索引も背景で構築する。
3. 未読込ページが必要な場合は、保存済み文字列のスナップショットを先に使う。自動準備のために全ページのOverlayViewModel・画像・サムネイルを生成しない。元PDFの文字抽出が必要なページは、既存隔離ワーカー経由で余裕のあるときだけ処理する。画像だけのページへ新しいOCRは実行しない。
4. 背景の辞書ジョブは文書ごとに1本とし、入力・描画・保存・利用者のOCR中は譲る。小分けの処理と中止／再開を使い、`Task.Run`だけで負荷制御を済ませた扱いにしない。
5. 準備前でも確認済み登録語は利用できる。未完成の全体頻度を完成値として使ったり、部分集計から自動補正したりしない。

既存の`IsBackgroundOperationVisible`をそのまま使うと編集不可条件へ波及するため、低優先度ジョブの状態を分離する。表示は下部ステータスバーとし、進捗が直前の編集結果や利用者の処理メッセージを上書きしないよう優先順位を設ける。上部の通知帯や常設説明文を増やさない。

### 差分更新

| 変更 | 必要な処理 |
| --- | --- |
| OCR文字の修正・追加・削除 | その領域の「索引へ反映済みの旧寄与」を除き、最新文字列の寄与を足す |
| 移動・サイズ・回転・読み順・表示モード | 語と頻度の再集計はしない。移動先の座標は領域IDで最新値を参照 |
| 固定／固定解除 | 頻度は再利用し、候補の編集可否と現在性を更新。既存の固定保護は緩めない |
| 正解語・ルール・無視語の変更 | 辞書世代を進め、影響語の検索／候補だけを更新 |
| ページ追加・削除・置換・Undo／Redo | 影響ページ／領域の寄与を追加・除去。切り分け不能なら全体を安全に失効 |
| 別文書への切替・閉じる | 旧ジョブを中止し、結果を新しい文書へ公開しない |

短時間に`A→B→C`と編集した場合、未集計のBを引いて数を壊さない。索引に実際に反映済みの領域世代と最新スナップショットの差を使い、連続編集をまとめる。Undo／Redoでも世代を巻き戻さず、古い非同期結果が復活しないようにする。

### キャッシュの現在性

文書・元PDFの識別、対象ページと有効な編集文字列、辞書内容、抽出規則／索引の版を照合する。位置や表示倍率だけの変更で失効させない。全体ハッシュをキー入力や候補表示のたびに計算せず、領域単位の差分から背景で更新する。

候補は文書セッション・文字列世代・辞書世代のスナップショットへ結び付ける。表示中の候補が古くなっても原文・辞書・固定状態を照合し、古い候補をそのまま適用しない。再OCRの厳格な既存チケット検査も維持する。

背景集計の完了だけでは未保存化しない。明示的な辞書編集・本文の補正は正本の変更なので未保存化し、通常保存／復旧／Undoへ含める。

## 7. 保存データと資源の安全性

- 正本の辞書とキャッシュに、件数・語句長・JSON総量・索引量・比較回数・処理時間／キャンセルの上限を設ける。既存の登録／無視各2,000語、異なり語25,000等を初期の基準とし、日本語追加分も予算を共有する。具体値は試験で確定する。
- 新しい配列・文字列はJSONの読込前予算と意味検証へ追加する。重複ID、不正な制御文字、同一補正元の競合、語句長超過、ルールの循環を検査する。
- 予算内のキャッシュ破損・旧版・内容不一致は破棄して再生成する。正本の辞書破損は黙って消さず、理由を示す。ZIP安全上限に違反するアーカイブ自体は、キャッシュ扱いだからと無条件に許容しない。
- 完成しなかった全体集計を、確定した頻度として保存／自動適用しない。安全上限に達した場合も明示辞書は保持し、全体頻度が利用できないことを示す。
- 学習画像・全出現箇所・全OCR本文の複製を辞書へ入れない。圧縮後の追加容量と読込時間を測定する。辞書作成のためにプロジェクト全体を頻繁に書き直さない。

| 2 | 資料別辞書の保存・復元・管理UI・Undoを実装 | 旧形式読込、辞書往復、復旧、破損・上限、正本変更の保存状態を検証 |
| 3 | 背景準備、頻度キャッシュ、領域単位の差分更新 | 初期表示を妨げず、連続編集／Undo／ページ変更で件数が全体再計算と一致 |
| 4 | 再OCR照会・同文字数候補・確認画面を接続 | 生の結果を保持し、最終文字で画像調整、1回のUndo、古い候補拒否を検証 |
| 5 | 承認済みの明示ルール自動適用を実装 | 頻度だけで適用しない、競合／循環／固定を拒否、連鎖しないことを検証 |
| 6 | 全体の性能・UI・保存・配布を検証 | バージョン整合、資源、実OCR、関連機能と大きな資料での確認を完了 |

### 重点テスト

- 原語が同じ文字数の別単語、頻出する誤認識、複数候補、未知語、大文字小文字、数値、`」`と`j/J`、日本語登録語句、結合文字・サロゲートを含める。
- 通常の単語補正の文字数変化を残し、再OCR用だけ同文字数で絞れること。生の認識値と辞書補正値を混同しないこと。
- 連続編集・固定・行移動・ページ削除／復元・辞書変更中の分析・文書切替・終了・中止・Undo／Redoで、件数・選択・候補現在性・原OCRの保持を検証する。
- キャッシュ無し／有り／旧版／破損で同じ最終候補になり、集計完了だけでは未保存にならず、辞書変更は保存／復旧／Undoへ残ること。
- 小・中・450ページ相当の資料と安全上限付近で、初期表示、入力応答、背景CPU／メモリ、キャッシュ復元、温まった1行検索、プロジェクト容量増加を別々に測る。RapidOCRの推論時間と辞書の待ち時間を混ぜない。
- 速度は未計測。初期表示を待たせる同期集計を追加しないことを必須とし、温まった1行の候補検索は50ms以内を暫定目標とする（推論・画像調整は除く）。測定結果と条件を記録し、未達を隠して部分結果を完成扱いにしない。
- 現行の列見出しメニュー、16 DIPの単語表示、説明オンオフ、フッターの文字ボタン、キーボード、パネルの再表示を退行させない。将来のコード変更時は規定のリビジョン更新・Release・契約／版管理・関連診断・BuildPortable・最終照合を行う。
