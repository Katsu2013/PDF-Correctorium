## 利用者回答による確定仕様

dev.254の追補：文書未読込時の設定起動、Windowsの配色と独立した主／右クリックメニュー、OCR読込の前景色、灰色の区切り・パネル枠・選択ボタン外周を修正した。赤い選択状態は維持する。共通テンプレートは標準WPFのメニュー入力処理を使い、独自のキー／マウス処理は追加しない。[実装・検証](releases/v1.0.0-dev.254.md)。

1. 自動テーマはWindowsのアプリの明暗設定へ追従する。ダーク時もPDF紙面は原色を維持し、アプリUIだけを変更する。
2. 読み上げ範囲は「選択部分／現在ページ／現在ページから最後まで」の3種類を用意する。

選択部分は既存のOCR文字・行・段落の選択を利用する。画像だけのページは新規OCRを自動実行せず、既存のOCRコマンドへ案内する。

## 現行機能との関係・影響範囲

| 箇所 | 確認できた現状 | 変更する方向 |
|---|---|---|
| `App.xaml` | 共通ブラシと各コントロールの独自テンプレートがある。白・灰色等の直接指定も残る | 現在の寸法・操作を保ち、意味ごとの配色リソースへ統合する |
| 各ウィンドウのXAML | ダイアログにも背景・文字・選択・無効状態の色指定がある | メニュー・一覧・入力欄・ポップアップまで動的な色参照へ統一する |
| AvalonDock、`MainWindow.PropertyPanes.cs` | 別ウィンドウやC#で作るパネルに白背景等がある | 固定／浮動パネルとそのタイトル・タブ・境界を同じ配色へ追従させる |
| `Resources/ActionIcon.cs` | 前景色を継承する図形、青いリンク、赤いPDF、白い細部がある | 形状を変えずに両テーマで確認。黒固定・白い面の役割を区別する |
| PDF描画、OCR枠、検索マーカー | 文書色と編集用の色がUIの色と混在する | UIの置換対象と文書表示を分ける。選択・ロック・差分の意味を保つ |
| `ApplicationSettingsService`、設定画面・設定転送 | 言語・表示・ツールバー等をアプリ単位で保存する | テーマ、音声ID、速度を共通設定へ追加。不正値・未導入音声・旧設定も扱う |
| `OcrModels`、`OverlayRegionViewModel` | 読み順、修正後文字、読み仮名、読み上げ参加属性が存在する | 保存済み状態と未保存編集の両方を読み上げ対象へ反映する |
| PDFワーカー | 文字だけの走査、文字と座標の抽出がある | 必要ページを隔離ワーカーで遅延取得。読み上げのために画像を生成しない |
| `MainWindowViewModel.DataExports` | TXTは墨消し前の情報も含み得る作業データ出力 | 出力処理をそのまま流用せず、参加属性・墨消し・座標を扱う読み上げ専用の整形を設ける |
| アプリ終了・文書切替・編集・Undo | 既に非同期処理の世代管理と取消がある | 音声・取得・ハイライトも寿命を管理し、古い文書の続きを再生しない |
| 配布と診断 | 自己完結型ZIP、MSIX、依存資源ロックがある | 音声ライブラリを採用する場合は版・ハッシュ・ライセンス・配布資源も更新する |

## テーマの操作と実装案

- 設定の表示タブに「テーマ：ライト／ダーク／Windowsに合わせる」を追加する。アプリ全体の設定とし、文書の未保存状態に影響させない。
- 保存後すぐに既存ウィンドウへ反映する。PDFを開き直したり、ドッキング配置を作り直したりしない。
- 共通配色は背景、入力面、浮動面、文字、補助文字、境界、選択、ホバー、押下、無効、警告等の役割で定義する。同じ色値でも文書の白とUIの白を機械的に同一視しない。
- 現在のテンプレート・操作寸法・アイコン形状を維持する。WPF Fluentを読み込むだけでは、独自テンプレートやAvalonDock内の直接指定色までは統一されない。
- 実行時の変更を受けるブラシは `DynamicResource`、C#で生成するコントロールは `SetResourceReference` 等で追従させる。各フレームでVisualTreeを巡回しない。
- 自動はOS通知を受けたときだけ更新し、一定間隔の監視を行わない。高コントラスト設定も確認する。ウィンドウ枠・タイトルはWindowsの対応APIで追従させる。
- PDF表示倍率・OCR位置・保存PDFの色・印刷結果はUIテーマの変更で変えない。紙面用の暗い表示を追加する場合は、表示専用の別仕様として確定する。

WPFにはLight／Dark／Systemのテーマ機能がある一方、現行の `Application.ThemeMode` は実験的APIとして記載されている。既存デザインの維持と、直接指定された色の解消を優先して採用方法を決める。

## 読み上げの操作案

- メニューから開始でき、再生中は小さい操作バーを表示する。再生／一時停止・再開／停止と現在のページ・行が分かる表示を用意する。
- 再生・停止等は既存方針に沿うMaterial系アイコンと操作名ツールチップを使う。音声・速度は設定または展開メニューへまとめ、常設ボタンを増やしすぎない。
- 読み上げ箇所はOCR枠の表示設定にかかわらず一時マーカーで示す。通常の文字選択を上書きしない。
- 選択範囲、1ページ、連続読みのどれで開始するかを明示する。利用者回答により初回から3範囲を用意する。
- 音声と速度はアプリ全体で保存する。再生中の状態はプロジェクトへ保存せず、起動時に自動再生しない。

## Windows標準音声の候補

第一候補はMicrosoftの `System.Speech.Synthesis.SpeechSynthesizer` とWindowsのSAPI音声エンジン。既存のWPFターゲットを維持しやすく、非同期再生、一時停止、再開、取消、音声列挙、速度調整、進捗イベントを利用できる。

初期調査ではWindows標準エンジン経由で日本語のMicrosoft Haruka Desktopと英語のMicrosoft Zira Desktopを列挙した。その後、.NET 10アプリの実サービスでMicrosoft日本語音声をWAVへ非同期合成し、一時停止・再開要求後の取消と、空でない音声データを確認した。試験ではスピーカーへ再生していない。MSIXを実際にインストールした状態の音声動作は未検証。

音声列挙とエンジン初期化は読み上げを開いたときに実施し、通常の起動・PDF読込へ追加しない。文書言語に対応するWindows標準音声を既定候補とする。端末ごとに音声は異なるので、未導入時は選択状態を復旧できる表示にする。レジストリの音声登録や音声モデルの導入を自動で変更しない。SAPIから列挙できる音声とナレーター／WinRTの音声が必ず一致するとは扱わない。

## 対象文字と処理の軽さ

1. 校正中のOCRは未保存の修正文を優先する。保存済み読み順・参加属性・読み仮名も尊重する。OCRのある箇所と元PDF文字を二重に読み上げない。
2. OCRのないページに元PDFの文字がある場合は、文字だけを遅延抽出する。画像のみのページでは勝手にOCRを開始しない。
3. 削除済み・読み上げ対象外の領域と、墨消し対象文字は除外する。文字単位で安全に分離できない墨消しの交差行は読み上げない。作業データ出力の文字列をそのまま音声エンジンへ渡さない。
4. 長文を一度に合成せず、行等の小さな単位で非同期再生する。連続読みでも、現在ページと次ページ程度の準備に抑える。
5. 読み上げ文字列をマークアップとして解釈させない。音声進捗の文字位置と画面のUnicode文字・読み仮名の対応を管理する。
6. 文書切替・終了・対象文字の修正は取得・音声・マーカーを取消す。世代の古い音声イベントを画面へ反映しない。墨消し予定がない場合の位置だけの変更では本文を再走査せず、安定した領域IDでマーカーを更新する。墨消し予定がある文書の配置変更は、古い除外判定を取消す。
7. dev.253では、編集後・元のOCR枠・墨消し元領域IDを合わせて判定し、いずれかが墨消し対象なら行全体を除外する。未保存の取込行にも実際の元座標を保持する。枠を動かしても除外対象を読み上げへ戻さない。

実装にはMicrosoftのSystem.Speech 10.0.14（MIT）を使用し、ライブラリとライセンスを依存ロックへ追加した。音声モデルは同梱しない。Windowsの既存SAPI音声を利用する。

## 実装・検証の順番

1. 利用者回答で確定した仕様を、要件・画面・設定設計に反映する。
2. 次の開発リビジョンで共通配色、設定保存、OS通知、主画面・ダイアログ・浮動パネルの配色を実装する。
3. 音声取得・再生制御を画面から分離し、対象文字の構築と取消・世代管理を実装する。
4. メニューと操作バー、一時マーカー、音声・速度の設定を接続する。
5. Light／Dark／自動の起動時・実行時切替、設定移行・転送、全主要画面、浮動ウィンドウ、キーボード操作、アイコン・警告の視認性を確認する。
6. 日本語・英語・縦横混在、修正文・読み仮名、選択文字、墨消し、画像のみのページ、停止・再開・文書切替・終了・音声なしを確認する。長文書でも全ページ読込を開始条件にしないことを検証する。
7. Release、契約試験、版管理、関連する実画面診断を実施し、新しい自己完結型配布フォルダーとZIP／MSIXを作る。署名・Store公開・実導入の残条件は別途維持する。
