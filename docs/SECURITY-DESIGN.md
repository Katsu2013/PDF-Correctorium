# セキュリティ設計と正式公開条件

対象はWindows 10/11の通常ユーザー。外部PDF・プロジェクト・OCR・しおり・ワーカー応答を信頼しない。同じユーザー権限で既に実行中の攻撃者やOS／管理者の侵害を防ぐ設計とはしない。

## 信頼境界

文書処理は完全ローカルで、PDF・OCR本文の外部アップロードは行わない。利用者が実行するHTTP(S)リンクと更新確認、および設定されたWindowsの配布更新は許可する。これは2026-10-30に利用者が確認した方針であり、無断の文書送信を許すものではない。[具体例・既定上限・墨消し範囲](Local-Processing-And-Redaction-Scope.md)。

- 画面プロセスはファイル選択、入力予算検査、コピーの仲介、出力確定を担当する。文書内の名前はパスとして使わない。
- PDFiumワーカーと単独qpdfは能力なしのAppContainerで起動する。原本にACLを追加せず、専用領域にコピーした対象ファイルと実行用バイナリーだけを許可する。実行用領域は読取専用、作業領域は書込可能。ネットワーク能力を付与しない。
- ワーカーは停止状態で生成し、Job Objectのメモリ・プロセス数制限を適用してから再開する。隔離失敗時に通常権限で再実行しない。
- 親はワーカーの出力を信用しない。読込ハンドルの実体パス、ファイルサイズ、JSONの構造予算、PNGの寸法と画素数、プロトコルと標準エラー量を確認する。
- AppContainer内のqpdf子プロセスは同じ制限トークンを継承する。AppContainerのプロファイルと一時領域を終了時に破棄する。dev.224以降は親専用の所有者記録とOSロックを追加し、起動時に本人所有・親PID／起動時刻が停止済み・24時間以上前の管理領域だけを排他ロックと実体パス検証後に限定清掃する。再解析ルート・稼働中／不明な所有者・古い形式の未知領域は自動削除しない。異常終了時の即時消去や暗号消去は保証しない。
- Release診断は実配布検証のため有効のまま。既存のオプション形状ファイル／ディレクトリが起動引数に含まれる場合、全診断分岐より通常ファイル起動を優先する。
- PDF出力の進捗・起動準備通知は250ms以内の共有競合再試行後にスキップ可能。取消は伝播する。最終完了・失敗通知は5秒上限の必須書込とし、検証結果を得られない出力を成功として確定しない。

## 入力予算

プロジェクトJSONは実読込バイト制限に加え、モデル構築前に全トークン・深さ・文字総量・オブジェクト数・配列数を検査する。未知フィールドも計数し、大小文字だけ異なる重複プロパティも拒否する。OCR文字・文字送り・ページ別領域・全体領域には個別上限がある。

しおりXMLもDOM生成前に全ノード・属性・構造深度・文字量を検査する。DTDと外部実体は禁止する。JSONは事前検査後にモデルへ直接復元し、テキストは読込途中で行長・行数・総文字数を制限する。

## 墨消しの保証範囲

対象ページの指定範囲の表示・本文文字を除去し、出力を再検証してから確定する。墨消しがある出力では既存の構造ツリーを除去し、アクセシビリティ情報の損失を警告する。読み方の出力が必要な場合は、墨消し対象等を除外した安全な範囲だけで新しい関連付けを構成する。古い構造や代替文字列の残存をqpdf等で再検証する。回帰試験では本文と構造ツリー、インラインのActualText／Altに同一文字列を入れ、出力のQDFにも残らないことを調べる。

墨消し範囲外の別ページ、しおりタイトル、文書情報、添付ファイル等に意図的に複製された全ての同義情報を検出する意味ではない。任意PDFの全ての秘匿情報除去を認定したものではなく、正式公開前に独立したレビューが必要。プロジェクトは復元・再編集用に原本や編集前データを保持するため、墨消し済みPDFと同じ秘匿性を持たない。機密共有物は完成した出力PDFを対象とする。

## 配布と保守

dev.271のソースから、build-info schema 2へ配布全件のパス・サイズ・ハッシュを記録する。NewReleaseStageはその一覧だけを別の新しいフォルダーへコピーし、元の利用者データを削除しない。通常の梱包と公開判定は生成データ・未記録／改変／欠落ファイルを拒否し、完成ZIPも全件照合する。利用済みの旧ビルドへ一覧を後付けし、認証済みとして扱わない。処理は開発・配布時だけに行い、利用者の起動経路にハッシュ全件走査を追加しない。

BuildPortable.ps1は証明書のthumbprintとWindows PowerShell 5.1対応のHTTP Authenticodeタイムスタンプサーバーを指定した場合、EXEと自社DLLを署名した後に版番号・ハッシュとbuild-infoを記録する。秘密鍵はエクスポートしない。証明書未指定の開発ビルドは未署名のままとし、署名済みとは表示しない。

TestReleaseReadiness.ps1は正確な配布先、全件一覧、クリーンなGit出所、ソース指紋と版数に結び付いた試験結果、30日以内の依存関係レビューと独立レビュー、タイムスタンプ付きの有効な署名を要求する。依存レビューはロックされた実バージョンにも一致させる。PDFium・qpdf・管理パッケージ・.NET Desktop Runtimeの一次情報で既知の脆弱性を確認する。依存ファイルのハッシュ一致は脆弱性がないことの証明にはしない。

証明書、第三者監査、非公開の脆弱性受付窓口、セキュリティ修正版の配布手順が未確認なら正式公開条件は未達とする。今回は公開・署名・第三者の承認を代行しない。既存の版番号運用は引き続きVERSIONING.mdに従う。
