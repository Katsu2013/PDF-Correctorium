# 自動収納タブと展開幅（dev.263）

2026-10-29。利用者確認により、タブは既存アイコンと文字を併記して約32論理px幅へ拡大する。展開時は収納前の幅を引き継ぎ、以前保存された極端に狭い値だけを補正する。

## タブ

dev.266で収納操作を左右別の一括、固定操作を個別へ統一する。後から開くパネルの追従と保存は[追加仕様](Chapter-Grouping-And-Side-AutoHide.md)を正とする。以下の寸法・幅継承は維持する。

ページはThumbnail、しおりはBookmark、OCR・校正はOcrEdit、リンクはLink、墨消しはRedaction、コメント・タグはComments、読み上げはReadAloudを共用する。独自の複合アイコンを増やさない。アイコンは20論理px、文字は12論理px、当たり領域の短辺は32論理pxとする。左右端では文字の既存回転を維持し、アイコンを逆回転して正立させる。ツールチップ・操作名はパネル名に合わせる。明暗の配色は共通資源を参照し、ネイティブのクリック・ピン・ドラッグを維持する。

## 展開幅

現行AvalonDockの既定では、自動収納の幅が未設定の場合に100pxへ縮む。表示メニューの独自操作だけでなく、ネイティブのピン操作でも収納前の幅を取得する。パネルを移す前の親コンテナのピクセル幅を優先し、星指定では現在の表示幅を利用する。未確定ならアプリの既定幅へ戻す。ユーザーが収納中の展開領域を広げた場合は、その幅を閉じる／再表示・再起動へ保持する。

幅の下限はページ・しおり200論理px、プロパティ・読み上げ240論理pxとする。以前の0／100px等の保存値は、アプリのページ幅／プロパティ幅を使って補正する。有効な展開幅は再起動時に上書きしない。収納後に固定へ戻し、再び収納した場合は、その時点の固定幅を引き継ぐ。モデルのイベントで処理し、スクロールやフレーム毎に内容を測定し直さない。

プロジェクト形式1.14／最小読込dev.262、設定21と依存ライブラリは維持する。ネイティブのレイアウトXMLを引き続き利用する。ピンとメニューの両経路、既存の狭い保存値、有効幅の保持、実際に開いた領域の寸法とアイコンの描画、左右・明暗・DPI相当の表示を確認する。

調査対象は同梱4.74.1に対応する[LayoutAutoHideWindowControl](https://github.com/Dirkster99/AvalonDock/blob/028a5f328eb86a7abfb2195bbaae37683c818d1e/source/Components/AvalonDock/Controls/LayoutAutoHideWindowControl.cs)と[LayoutAnchorable](https://github.com/Dirkster99/AvalonDock/blob/028a5f328eb86a7abfb2195bbaae37683c818d1e/source/Components/AvalonDock/Layout/LayoutAnchorable.cs)。ライブラリ自体の変更や更新は行わない。

dev.263の配布版で実表示・幅復元を含むパネル診断203項目と、既存機能の回帰を通過した。[検証結果・配布先](releases/v1.0.0-dev.263.md)。
