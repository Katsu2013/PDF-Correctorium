# PDFへの読み方保存と出力負荷の削減（dev.267）

2026-10-29。読み方をPDF出力でも保持する要件を実装する。確認用ルビの表示と、PDFの読み上げ用情報を明確に分離する。

dev.269で方針確定：原文の検索・コピーを維持し、現行のAlt＋言語情報を保存する。「Node.js」のドットを読んだり、短い間が入ったりする差は利用者が許容した。外部リーダーで登録読みへの完全一致を保証せず、出力完了の「保存した読み方情報」は保存件数を表す。アプリ内読み上げでは登録読みを利用する。詳細と実機結果は[リーダー互換性](Pdf-Reading-Interoperability.md)へ記録する。

## 保存する情報

共通WordReadingsと行ごとの例外を、アプリ内の音声と同じ完全一致・最長一致・Unicode書記素境界で照合する。行の例外を優先する。文字や位置を編集していない行も対象とし、IsModifiedに依存しない。出力対象外・読み上げ対象外・削除済みの行は除く。未使用の辞書語をPDFへ余分に同梱しない。

本文の文字コード、ToUnicode、文字位置をかなに置換しない。確認用ルビも描画しない。読み方を適用した行に、PDFの標準論理構造の代替テキスト（StructElem /Alt）を付ける。文字オブジェクトのMCID、ページのStructParents、構造のParentTreeを相互に結び、通常の文字も同じ構造から読めるようにする。未タグ付けのForm XObject内の通常文も呼び出しを関連付け、読み順から落とさない。かなを含む代替テキストにはja-JPを指定する。PDF 1.4～2.0の選択を維持し、出力バージョンを勝手に上げない。

PDF 2.0のPhonemeは音声記号体系を伴う別の機能であり、かなをIPAと偽って保存しない。今回は読み上げ用の人間可読テキストをAltとして保存する。アプリ共通の読み方辞書、行の例外、保存形式1.14／最小読込dev.262、設定21は変更しない。

## 既存構造と検証

既存タグは、対象の文字との対応が厳密に確認できる場合に更新する。タグの所有する文字が他の行を含む場合や、対象が複数の既存タグに分かれ、安全な対応を確定できない場合は出力を中止して理由を表示する。本文や他のアクセシビリティ構造を黙って置き換えない。新規MCIDの衝突、タグの循環、過剰な深さ／範囲を検査する。

保存した行数は出力結果へ表示する。保存した実ファイルをPDFiumの構造APIで開き直し、期待した読み方を取得できた場合だけ保存先へ確定する。失敗時に読み方なしのPDFへ黙って切り替えない。本文抽出と画素比較もアプリ診断で検証する。PDF/UA準拠や、すべてのリーダーでの読み上げ対応を意味するものではない。

Altを実際の音声に利用するかはリーダーに依存する。PDF内の保存・再読込と、特定リーダーの読み上げ動作は別に検証する。BOOX、Android版／PC版Acrobat、Audify 読み上げ Web ブラウザの実機結果を受領した。最新の指示は全出力で検索・コピーの原文維持を必須とし、透明OCR本文の置換と読み方をActualTextに入れる方式を不採用とする。以前の任意互換出力案は撤回。現在の本体はAlt方式のままであり、発音指定専用情報は[互換性調査](Pdf-Reading-Interoperability.md)で検証する。

## 墨消し

元位置または編集位置で墨消しと交差する行、その行自体を対象とする墨消しには読み方を付けない。古い構造ツリーを除去してから、消去後の実在する文字と安全な読み方だけで構造を再構築する。旧ページ・注釈の親キーを新しいParentTreeへ誤接続しない。

画像化するページに読み方が必要な場合、範囲外の可視文字も元の文字／位置を保った不可視テキストとして保持する。見た目は画像へ一度だけ反映し、二重に描画しない。境界の判定・部分的な文字除去は既存の保護処理を共用する。範囲内の読み方を復活させない。

## 出力負荷

- 変更していない既存リンクをページ単位で再確認しない。追加・修正・削除があるページだけを既存の注釈照合へ通す。しおり・リンク・読み方構造は最後のqpdf更新へまとめる。
- 文字／画像／装飾を変更していない非暗号化PDFは、最初の無変更なPDFium再保存をコピーへ置き換える。暗号化PDFは従来の再保存経路を維持する。
- 文字校正も読み方も不要なら、校正用のPDF再読込を行わない。読み方のMCID追加は既存の校正用ドキュメントで行い、別の保存工程を増やさない。
- 本処理は既存の分離ワーカー内で行う。元PDFを直接書き換えず、出力検証・墨消しの安全処理・保存先の競合確認を省かない。

20ページの実リンクを含む検査では、変更なしのリンク反映が文書更新全体でqpdf 4回に収まることと、元のリンク先が維持されることを確認する。所要時間は証跡JSONへ記録し、任意の実文書で同じ短縮率になるとは主張しない。

## PDFiumの改行ハイフン（dev.268）

PDFiumは行末のハイフン（U+002D／U+00AD）を、文字抽出時にU+0002へ変換する場合がある。読み方の対応付けでは、このマーカーに限って元のハイフンと同一と判定する。ハイフンを削除したり、他の制御文字や異なる文字を一致扱いしたりしない。本文・字形・見た目・既存の出力検証は変えない。

実際に提供された450ページのプロジェクトの269ページで、`package.json/package-`の末尾がU+0002となることを確認した。折り返したファイル名、再出力、元の文字抽出、画素一致、真の不一致の拒否を回帰検証する。
