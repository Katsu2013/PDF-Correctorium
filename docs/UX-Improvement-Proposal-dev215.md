# PDF Correctorium 操作・独自機能改善提案

検討日：2026-10-07。基準：現行ソース `1.0.0-dev.215`。

2026-10-07に改善方針の実装を承認。段階的に採用する。dev.216の実装対象と受入条件は[OCRプロパティ改善設計](UX-Ocr-Properties-dev216.md)に切り出した。変更前後の比較、固定端の新規オーバーレイ、疑わしい候補の進捗管理などは後続段階であり、この提案全体を実装済みと扱わない。

## 1. 到達したい体験

「使い方の文章を読んでから操作するPDFエディター」から、「文書を見て、対象を選び、変化を確認して仕上げる校正ワークベンチ」へ進める。

独自性の中心は、日本語のスキャン文書について **認識文字と画像の対応が見える／文字境界まで直せる／繰り返し作業をまとめられる／元資料を壊さずやり直せる** こと。本文直接編集などの汎用機能は別の開発線とし、まずこの体験を完成させる。

無料・ローカル処理・ポータブルだけを独占的な強みと扱わない。市販品の機能数を追うこと、認識精度や安全性で無検証の優位を主張することは目的にしない。

### 利用者から確定している方針

- 長い説明をプロパティへ常設することを初心者対策の中心にしない。
- 操作の直感性・快適性と独自の強みを高める。
- 可読性・保守性・動作の軽さを重視する。
- 既存の承認済みアイコンと、ダイアログ下部を文字のみとする規則を維持する。

以下の具体的な配置、名称、既定値、新規操作はすべて提案である。

## 2. 現行の観察と改善対象

| 現行の構成・制約 | 改善案 | 単に削ってはいけないもの |
| --- | --- | --- |
| モード、OCR編集単位、選択対象、準備状態の組合せで操作可否が変わる | 現在対象・作用範囲・状態を短い固定欄で明示する | 明示的なモード、入力欄のフォーカス、未確定編集 |

| 自動調整の行全体／選択以降の区別が小さなアイコンと説明に依存する | 操作名と対象範囲を隣接表示し、プレビューで変化を見せる | 接頭部分・固定文字・領域ロック・単一Undo |
| OCRとリンクの整列基準や変形可能な対象に差がある | 共通の見た目に加え、実際の基準対象を枠上で明示する | 既存の基準規則。統一目的で意味を変えない |

| 表示ページ優先と背景準備が既にある | 対象ページの準備状態を操作の近くに表示する | 未読込をゼロ件扱いしない、保存／出力時の全体検査 |

「説明がすべて表示される」「すべての無効操作が理由不明」といった新たな不具合を確認した記録ではない。構造・発見しやすさの改善案である。

## 3. 共通操作モデル

### 3.1 モードと選択を混同しない

- 大分類の編集モードは維持し、文字ラベルと選択状態で示す。選択やタブ閲覧だけでモードを自動変更しない。
- パネルの閲覧タブと編集モードは引き続き別。現在モードではないパネルは、上部に短い状態表示と切替操作を1か所だけ置く。閲覧可能な内容まで全体を無効にしない。
- OCRの文字／行／段落は、OCR作業の近くで選択する。編集単位の変更を、見開き／スクロールやツールバー配置と結び付けない。
- 「選択文字からリンク作成」などの明示操作は既存選択を使って処理し、完了後は元の作業へ戻る。無言で別モードへ移さない。リンク先を調整したい場合のみ明示的な継続操作を用意する。
- 操作完了だけでは自動で次の文字・対象へ移動しない。「確認して次へ」は別の明示操作として維持する。

### 3.2 プロパティの順序を固定する

各パネルを上から次の順にする。詳細内部の配置まで同一にするのではなく、読み取りと判断の順序を揃える。

1. **現在の対象と状態**：例えば「PDF 7ページ／OCR 1行／3文字選択」「文字位置固定」。色だけに頼らない。
2. **よく使う操作**：OCR訂正・画像からの境界調整、リンク先変更、墨消しの色・範囲調整など。
3. **選択対象の内容**：文字列、リンク先、墨消し予定など。編集できる欄と読み取り専用の欄を区別する。
4. **詳細**：座標、幅、高さ、回転、推定パラメーターなどを明示展開する。

見出し・主要ボタン・入力欄の位置は安定させる。同じ操作文脈で選択が変わるたびにボタンを並べ替えない。文脈外の機能は隠し、文脈内で条件が足りない操作は同じ位置で無効化し、隣接した状態欄で理由を示す。

未選択時は多数の無効ボタンではなく「対象未選択」と少数の作成操作を示す。長い指導文は置かない。実際の作成操作なしでチュートリアルへ誘導する画面にしない。

### 3.3 操作の入口は整理するが、右クリック専用にしない

- 文書を開く／保存／PDF出力、ページ閲覧は安定したツールバーに維持する。
- 対象依存の操作は、プロパティの固定した操作欄、右クリック、既存ショートカットで提供する。同じ操作の範囲と効果を一致させる。
- 文書上の常時浮動ミニツールバーは初回案では採らない。文字を覆う、狭い画面で衝突する、キーボードで辿りにくいリスクがある。
- コピー・削除などは文字入力欄とキャンバスで対象を明確に分ける。Del、Enter、Escを一律に全体コマンドへ横取りしない。
- 固定欄の外に追いやる詳細機能にも、メニュー／キーボードから辿れる経路を残す。

## 4. 説明文の置き換え

| 情報 | 提案する扱い |
| --- | --- |
| 長い一般操作説明 | プロパティの常設から外し、必要時に開く操作ガイドへ移す |
| 操作名・作用範囲 | ボタン・対象欄に短く表示。例「選択文字以降の境界を調整」 |
| 描画途中の状態 | 選択形状、ラバーバンド、頂点、ハンドル、固定端をページ上で表示 |
| 操作不能の理由 | その操作グループの近くに短い状態と解決操作。例「固定中」＋「解除」 |
| 入力エラー | 入力欄の近く。正しい値を推測して黙って書き換えない |
| 読込・処理状態 | 未準備／処理中／完了／中止を区別。操作ごとの段階と進捗を表示 |
| 情報漏洩・出力方式・検査失敗 | 必要な段階で必ず表示。一般ヘルプOFFの影響を受けない |
| アイコンの名称 | ホバーとキーボードフォーカスの短いツールチップ、アクセシブルな名称 |

ツールチップは補助であって、不可欠な操作を発見する唯一の経路にしない。既定で長い説明を隠す案でも、意味のある操作名・対象・安全情報は消さない。既存の説明ON/OFFをどの操作ガイドへ移行するかは実装前の承認事項である。

## 5. 独自の強みを育てる3つの作業

### A. 精密OCR校正：文字と画像の対応を見ながら直す

#### 基本シナリオ

1. 行または文字を選ぶ。ページ上とプロパティの両方に選択範囲を示す。
2. 「画像に境界を合わせる」の対象を「この行」「選択文字以降」から選ぶ。対象をボタンの近くに常時示す。同じ操作文脈内の前回範囲は記憶候補だが、対象不適合なら明示する。選択変更だけでは解析しない。
3. 利用者が実行したときに推定する。単一行の通常操作は現在と同じ直接適用＋Undoを基本にし、必要時に変更前後を同じ位置・同じ倍率で比較できる。適用前に見たい場合は「確認して適用」を明示選択する。文字を勝手に置換せず、境界を対象にする。
4. 採用後、固定する／次の対象へ進む／さらに手動調整する。確定は1回のUndo。

一括と精密手動操作を同じ推定・候補・履歴の仕組みへ載せる。全操作に確認ダイアログを足すのではなく、複数対象の処理は「比較して採用」、通常の文字訂正・1px境界移動・ドラッグ・単一行の明示調整は直接適用＋Undoを基本にする。直接適用後の比較は表示だけであり、他の編集が進んだ後に古い比較結果を再適用できないようにする。適用前候補は未保存状態に影響させない。既定動作は実装前の承認事項。

#### 強化項目

- **固定された文字と作用範囲の可視化**：小さな錠表示と選択端の強調。選択前の固定範囲を含めて動く／動かない箇所が見える。
- **境界編集の直接操作**：字形に沿う境界ハンドルと拡大補助。横書きは横軸、縦書きは縦軸。拡大補助は現在領域だけを使い、OCRを再実行しない。固定文字を押し動かさない。
- **対象範囲の追加候補**：「選択文字だけ」の調整を新規機能として検討する。現在の行／選択以降とは別で、両端固定・総幅維持・ロック整合性を確認してから実装する。
- **画像／認識文字の見比べ**：元画像と現在文字列の対応を比較できるが、元画像を可視本文へ置換する機能とは区別する。長押しだけではなくキーボードでも切替可能にする。
- **「疑わしい箇所から直す」**：境界の交差、範囲外、点数差など根拠のある候補を提示し、画像と文字を並べて確認する。統計的に校正されていない信頼度を「正答率」と表示しない。「候補なし」を正しい全文と扱わない。
- **全体進捗**：利用者が確認した件数と自動検出候補数を分ける。ページ未読込や未解析を「確認済み」にしない。評価済み結果を編集対象だけ無効化し、パネル開閉で全文を再解析しない。

### B. 本の目次・索引を使えるリンクへ仕上げる

現行の行末整数＋番号差から、確認しやすいブック向けワークフローへ進める。

1. 「このPDFページが印刷上の1ページ」を実際のページを見て指定する。計算された差も表示する。
2. 目次範囲を選び候補を作る。目次の該当行と移動先ページを対にして比較する。
3. 存在しないページ、既存リンクとの重複、判別できない番号は別状態で表示する。
4. チェックしたものだけ適用する。新しい候補で既存リンクを黙って上書きしない。

将来のローマ数字、前付け／本文の複数区間、章単位でリセットする番号は別段階。区間を利用者が指定する方式を先に検討し、任意の目次を意味理解する自動化を初回へ詰め込まない。しおり生成もタイトル階層の根拠とプレビューが準備できるまで別機能とする。

OCR訂正からリンク作成まで選択文字と同じ範囲を再利用する。複数行リンクは行間を含む巨大な矩形へ変えない。配置合わせでは既存の基準対象を視覚表示し、OCR側の基準をリンク側の「最初に選んだ矩形」へ無断変更しない。

### C. 墨消しを「指定」と「配布用成果物」に分けて理解できるようにする

- 編集中の範囲は「墨消し予定」。半透明／不透明は編集上の確認表示にすぎず、保護状態を示さない。
- 「指定した文字」と「ページ画像化」の方式差を出力直前に対象ページと一緒に示す。方式を無言で切り替えない。
- 一括検索の一致範囲を画像と並べ、候補ゼロでも「情報はない」と断定しない。画像のみのページ・未認識文字は検査範囲外として示す。
- 出力は作成→再検査→確定を維持し、失敗は成果物を安全として提示しない。再検査の対象と対象外を明示し、「万能な安全認証」にしない。
- 出力後には「配布するファイル」を1つ明確に示す。元PDF・プロジェクト・バックアップは原情報を含む旨をその段階で示す。プロジェクトを自動削除しない。
- 通常のPDF出力へ毎回長い安全説明を追加せず、墨消し・未対応構造など該当する出力条件でだけ判断材料を出す。

## 6. 快適性を守る設計

1. 選択・ホバー・パネル閲覧でOCR実行、全ページ同期、全文検査を開始しない。
2. まず選択とハンドルを描画し、処理が必要なら処理中状態を示す。重い推定は明示実行時に対象領域の不変スナップショットで処理する。WPF部品を背景スレッドで触らない。
3. 比較は現在ページ／領域だけ。変更前後のプレビューは同じ表示変換を使い、全ページビットマップを2組保持しない。高品質PDF出力は別処理とする。
4. キャッシュは文書ID・ページ・編集世代・倍率／回転／切出し・設定で識別し、件数とメモリーを制限する。候補変更で破棄し、プロジェクトへ保存しない。
5. 古い背景結果は文書・対象・世代が一致する場合だけ適用する。入力値変更・文書切替で比較候補を無効化する。中止後も共有の通常読込を不用意に止めない。
6. ドラッグ中は表示位置を変更し、確定時に1回だけ履歴を作る。計算やディスク書込を毎マウス移動で行わない。
7. 座標更新・パネル内部更新とドッキング復元を分離する。新しい基本／詳細配置でAvalonDockツリーを再生成しない。
8. 長い一覧は仮想化し、プレビューは選択ページだけ。推定候補の確認を新しい巨大な一括同期処理へ置き換えない。

## 7. 保守性と影響範囲

### 提案する実装境界

- 既存のICommand、対象ID、ページ座標変換、編集履歴、解析サービスを再利用する。画面ごとに判定や推定コードをコピーしない。
- 共通の「現在の操作文脈」をモード／編集単位／選択種別／対象ID／準備状態／ロック／実行中の値として扱う。これはUI表示のための派生情報で、文書の新しい正本にしない。
- 操作可能条件と短い不可能理由を同じ規則から得る。UIを通さないコマンド実行でもロックや範囲を検査する。翻訳されたボタン文字列から動作を判別しない。
- 変更候補は正本とは別に保持し、未採用の比較でdirty／Undo／自動保存を変更しない。採用時だけ既存履歴へ1回追加する。通常のUndoから「変更前後比較」を実装しない。
- UI共通化はボタン、状態欄、比較部品から小さく始める。すべての編集を1つの巨大な汎用フォームや独自UIフレームワークへ作り直さない。
- 状態・ラベル・適用可否・ショートカット表示は各画面で統一し、設定の保存先を増殖させない。

### 影響一覧

| 領域 | 採用時に確認する事項 |
| --- | --- |
| MainWindow XAML／PropertyPanes | 基本・詳細配置、選択表示、名前スコープ、既存イベント、4パネルの独立閲覧 |
| ViewModel／コマンド | モード、編集単位、選択保持、CanExecute、ロック、入力確定、Undo／Redo |
| 画像解析・座標変換 | 元画像、回転・CropBox・倍率、縦書き、固定境界、候補整合性 |
| 背景読込・一括候補 | 待機・中止・結果世代、未準備状態、候補数上限、条件変更 |
| 設定・保存 | 説明表示の移行、詳細展開、既存配置復元、モード優先順位。文書状態をUI設定と混同しない |
| プロジェクト・出力 | 候補非永続、dirty規則、墨消し方式、元情報保全、出力後検査。UI変更だけでは形式を上げない |
| 共通アイコン／翻訳／アクセシビリティ | 承認済み形状、18/22/24px、名称、日英、Tab、フォーカス、色以外の識別、Footer除外 |
| 試験・文書 | 現行診断の継続、操作シナリオ追加、要求・画面・UX・データ・出力の採用範囲だけ同期 |

## 8. 比較検討して採らない案

| 案 | 見送る理由 | 代わりに採るもの |
| --- | --- | --- |
| 初心者用／上級者用の別画面 | 操作・試験・説明が二重化し、後から機能差が生まれる | 同じ画面の基本／詳細 |
| 長い説明をすべてツールチップへ移動 | 必要情報が発見できず、キーボード操作でも不利 | 意味のあるラベル、状態と結果、任意ガイド |
| 選択を見て自動モード変更 | クリックの意味が変わり、継続作業が予測できない | 明示モード、選択からの明示ショート操作 |
| 選択時に自動で解析・修正 | 遅くなり、意図しない変更・固定部分の破壊を招く | 明示実行、候補比較、単一採用 |
| すべての操作で確認ダイアログ | 精密作業のテンポを損なう | 局所編集は直接＋Undo、複数対象・危険操作は確認 |
| すべての候補をAIで自動承認 | 判断根拠・漏れ・処理負担が不明 | 観測可能な根拠を示す候補と人の判断 |
| 全機能を一度に再配置 | 使い慣れた操作とドッキングを同時に壊す | OCRの1パネルと共通状態から段階導入 |

## 9. 実装順序と採用ゲート

規模は相対評価であり工数の確約ではない。最初の段階は画面見本と操作シナリオの承認。次に限定範囲を実装し、利用者が同じ資料で試した結果で次段階を判断する。

| 順序 | 内容 | 相対規模 | 終了条件 |
| --- | --- | --- | --- |
| P0 | 対象・作用範囲・ロック・未準備・危険情報の共通規則を確定 | 小：設計 | 状態表と画面見本、例外操作の合意 |
| P1 | OCRプロパティの基本／詳細、短い名称、長文常設の整理 | 中 | 初見操作、精密作業、日英・狭幅・配置復元の確認 |
| P2 | OCR境界調整の任意前後比較、固定範囲表示、一括候補の1回採用 | 中〜大 | 単一行の連続作業を遅くせず、実PDFで効果・負担・ロック・Undo・候補破棄を検証 |
| P3 | 同じ状態・対象規則をリンク／墨消しへ展開、墨消し出力表示を整理 | 中 | 既存コマンド意味と安全規則を維持、機能間の操作差を再検査 |
| P4 | 校正候補の根拠表示・確認進捗、目次番号対応の実ページ指定 | 中〜大 | 候補と確定の区別、未解析の識別、選択ページ優先が維持 |
| 別系列 | 内蔵OCR、区間番号、汎用PDF本文／画像編集、標準PDF注釈 | 各別見積り | モデル・エンジン・ライセンス・配布・出力互換性を別途承認 |

内蔵OCRは強みと親和性があるが、P1のUI整理へ混ぜない。既存の外部NDLOCR取込を残し、モデル容量・更新・認識結果の差分採用・背景処理を別設計で扱う。

## 10. 受入シナリオと評価

### 操作の確認

- 説明を常設しない状態で、初見の利用者が「OCR文字を直す」「選択以降を調整する」「リンク先を変える」「墨消し予定を作って出力する」を試す。まず少人数の形成的テストで躓きを探し、市販品より優れるという統計的結論にはしない。
- 慣れた利用者が同じ実PDF・同じ選択開始位置で、現在版と候補版を比較する。クリック数、余分なスクロール、作業時間、誤操作、Undo回数を記録する。既存の逐字精密作業を遅くしない。
- 文字入力中のDelは文字削除、キャンバスのDelは対象削除。固定リンクの削除は拒否し、OCR等の他対象へ同じ削除規則を無断で一般化しない。位置固定と文字訂正可否も対象型ごとの既存規則を維持する。Escは未確定操作を取消し、確定済み変更を黙って取り消さない。既存のモード終了動作を変える場合は別途承認する。
- 未選択・1文字・複数文字・1行・複数行・固定対象・未準備ページ・異なるモードのパネル閲覧について、対象表示と実際の適用が一致する。
- 狭いパネル、縦ツールバー、高DPI、英語、キーボードのみでも操作が発見できる。右クリック、ホバー、色だけに必須操作を依存させない。

### 正確性と快適性

- 提供された450ページPDFの7ページ目に加え、縦書き、欧文混在、点数不一致、画像のみのページ、複数行リンク、回転・CropBoxを含む固定セットを用意する。
- 暖機後／初回を分け、選択から表示まで、推定、背景準備、候補切替、出力を別々に測る。単一行の数msを全体の性能値に読み替えない。
- 日常の選択・入力・ローカル表示操作は100ms以内に反応することを設計目標とする。認識や出力の完了時間を100msと約束しない。基準PCと測定条件を固定して判定する。
- 一括処理中も移動・中止に反応し、文書切替で古い候補を適用しない。未採用候補が保存・自動保存・Undoへ混入しない。
- メモリーは全ページ画像2組へ比例させない。プレビュー切替の反復で画像・イベント購読・浮動パネルが増え続けないことを確認する。
- 既存契約・版管理・キーボード・設定・プロパティ・リンク・OCR描画・文字幅・出力回帰を継続する。テスト合格と完全な安全性・PDF適合性は区別する。

## 11. 実装前に確認する選択

1. 長文の常設説明を外し、基本操作＋展開する詳細＋任意操作ガイドを基本構造とするか。既存「説明」表示設定の移行を含む。
2. 画像による自動調整は単一行の「直接適用＋任意比較／Undo」、複数対象の「確認して採用」を基本にするか。推奨は連続校正の速度を維持するこの分け方。単一行にも適用前確認を選べる入口を用意する。熟練者の実操作で決める。
3. モード選択は現在の省スペース一覧を維持するか、主要モードの文字付きボタンへ変えるか。狭幅・縦配置では簡潔な選択器へ切り替える見本も比較し、未承認アイコンは増やさない。

数字や初期値を確認なしで設定へ書き込まない。各段階の具体見本を承認してから採用する。
