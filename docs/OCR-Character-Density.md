# 文字数の外れ値 — 文字種補正と枠の比率

dev.237、2026-10-23。文字数の単純比較を、文字種に応じた幅換算量と枠の縦横比による候補抽出へ変更する。OCRの再実行、自動訂正、枠の自動変更ではない。

## 判定

1. Unicodeテキスト要素ごとに字幅の目安を合計する。横書きのCJK・全角は約1、欧文英数字は基本0.6、狭い欧文字・句読点は0.3、M/W/m/wは0.9、半角カナは0.5、内部空白は0.33とする。前後の空白は除く。濁点・結合アクセント・異体字セレクター等を別の文字幅に加算しない。補助漢字、ハングルの分解表記、結合絵文字もテキスト要素として扱う。
2. 横書きは`幅÷高さ`、縦書きは`高さ÷幅`を行の縦横比とする。`幅換算量÷縦横比`が文字密度となる。縦書きの欧文等は正立したセルを仮定して1とする。横書きの字幅をそのまま縦方向へ流用しない。
3. 同じ書字方向かつ行の太さが許容差内にある独立した領域を基準候補にする。横書きの太さは高さ、縦書きは幅。行の長さは一致条件にせず、密度で正規化する。同じIDの重複と自分自身は基準に含めない。
4. 基準に極端な誤認識を取り込まないよう、幅換算密度0.5〜2.0の領域から中央値を求める。最低比較件数に足りない場合や、中央50%の密度の上側／下側比が1.5を超える場合は判定しない。極端な密度の行も検出対象ではあるが、基準を作る票にはしない。固定済みの行は他の行と同条件で基準に参加する。
5. `対象行の密度÷基準中央値`を「密度比」とする。初期閾値1.6では、0.625以下を少なすぎる、1.6以上を多すぎる候補とする。丸め前の目安との差が2文字以上という保守的な条件も維持する。

`目安文字数 = 対象行の文字数÷密度比`。対象行自身の全角／半角構成を使った換算であり、欧文の多い他行の生の文字数を日本語行へ当てはめる値ではない。実際の文字数は従来どおりUnicodeテキスト要素数で表示する。枠の単位や一様な表示倍率には依存しない。

## UIと操作

- 「文字数の外れ値」タブは維持し、条件を「行の太さ許容差（%）」「最低比較件数」「密度比の閾値」とする。
- 「標準文字数」を「目安文字数」に改め、「密度比」を追加する。密度比は1前後が基準、低いほど疎、高いほど密。並べ替え、候補への移動、固定済みの表示切替は維持する。
- dev.238では基本列をページ・判定・OCR文字列・文字数・目安文字数の5列へ整理する。密度比・比較件数・幅・高さ・方向・固定列は「詳細列」で再表示する。固定済みを含めた時は基本の判定にも「固定済み」を添え、操作上の状態を隠さない。[一覧表示の共通規約](List-Presentation.md)。判定式はdev.237から変更しない。
- 明示的な分析はスナップショットに対して実施する。固定切替の表示追従を除き、文字や枠を変更した後の新しい密度判定には再分析が必要。通常のドラッグ中に自動分析は追加しない。
- 表示フィルターだけでは未保存にせず、元PDF・OCR文字・幾何を変更しない。

## 軽快さ

文字幅の計算は各行につき1回。書字方向別・太さ順のスライディング窓と順位木で中央値・四分位点を求め、全行同士の総当たりを避ける。計算量は概ね`O(文字量 + n log n)`、保持量は`O(n)`。比較計算はUIスレッド外で行い、準備・比較中のキャンセルを受け付け、途中結果は返さない。追加のPDF描画・画像解析・OCR・モデル読込・外部通信は行わない。

## 制約

これらはフォントの実測値ではなく、文書内の傾向で補正する字幅の目安である。極端な字間、複雑な組版・文字体系、縦中横・横倒し欧文、枠に含む余白、異なるフォントが混在する場合には過不足の候補が残り得る。明示的に改行を含む複数行の枠は単一行モデルで判定しない。基準不足・不安定な場合や文書の大部分が同様に誤っている場合の検出を保証しない。候補ゼロはOCRが正しいことの証明ではない。

## 検証

混在文字、画像で指摘された寸法、真の疎／過密、結合文字・濁点・補助漢字・ハングル・絵文字、縦書き、倍率、太さ別の基準、無効値・重複ID・不安定基準・キャンセルを契約テストで検証する。スライディング窓は独立した総当たり計算と照合し、25,000行の負荷試験を行う。実際の一覧・翻訳・ソート・固定フィルター・元プロジェクト不変もアプリ診断で検証する。実行結果と配布先は[dev.237検証記録](releases/v1.0.0-dev.237.md)に記載する。
