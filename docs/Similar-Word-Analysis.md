# 書籍全体の類似語・OCR誤認識候補（現行仕様dev.244）

dev.244では、登録した語句や明示ルールの未集計頻度は空欄とする。集計済みの英数字の頻度と混同しない。数値列の並べ替えは維持する。[最終検証](releases/v1.0.0-dev.244.md)。

## 共通の資料別辞書（dev.243）

「OCR → 資料のOCR辞書...」で正解語・訂正ルール・無視語をプロジェクトへ保存する。英数字用語と登録した日本語語句を扱い、RapidOCRの確認と共用する。頻出語は正解語とは別の参照情報。類似語の選択修正時に、任意の正解語／訂正ルール登録を同じUndoへ含められる。新規ルールの自動許可はオフ。無視語も画面限りではなく資料に保存し、Undoできる。現在世代の候補は再オープン時も保持し、明示的な分析で頻度を更新する。

新規保存は形式1.12／最低読込dev.243、設定21は変更しない。旧形式1.0～1.11を読み、正本辞書のない旧ファイルは空辞書として扱う。[共通設計](Shared-OCR-Lexicon-Implementation-Plan.md)。以下のdev.235までの記録はその版の挙動であり、辞書の一時保持に関する記述は本節で置き換える。

## 操作

1. PDFまたはOCR編集プロジェクトを開き、「OCR」→「OCR品質の異常候補...」を開く。
2. 第3タブ「類似語・誤認識候補」で「文書全体を分析」を押す。現在編集中のOCR文字列を全ページから集計する。未表示ページも対象。解析中は進捗表示とキャンセルを利用できる。
3. 現在の語・修正候補・双方の出現件数・理由・前後の文章を確認する。行をダブルクリック、または「選択箇所へ移動」で原画像と該当文字範囲を照合する。
4. Ctrl／Shiftで確認した行を選び「選択候補だけ修正」。確認ダイアログで承諾した箇所だけOCR文字列を変更する。固定済み領域／文字は変更しない。修正後は「要再確認」となる。一括操作は1回のUndo／Redoで戻せる。
5. 選択修正した候補だけを除き、残りは文字オフセットを更新して保持する。PDF上のOCR行の移動・サイズ調整・回転、配置だけのUndo／Redoの後も続けて修正できる。頻度は分析時の値であり、最新頻度が必要なら再分析する。文字列・追加／削除・固定状態・ページ構成や文書が変わった場合は再分析し、古い候補を適用しない。

## 配置調整と分析の現在性（dev.235）

OCR文字分析の世代は、通常の未保存状態や編集履歴とは分ける。行の位置・大きさ・回転・文字送り・読み順・確認ステータスの変更では、語や出現頻度の根拠は変わらない。これらの変更やそのUndo／Redoでは一覧・選択・並べ替えを維持し、再収集・再認識・全体再分析を行わない。候補への移動は行IDから現在の座標を使う。分析中の配置変更も中断理由としない。

文字、領域の追加／削除、行／文字の固定を変えたときは、巻き戻らない入力世代を進める。文字変更をUndoして元と同じ文字へ戻しても古い候補を復活させない。ページ構成・読込セッション・内容を分類できない変更は安全側で失効させる。選択候補の修正操作そのものは、原文一致を確かめたうえで残候補を新世代へ更新する。固定中の対象は適用直前にも拒否する。

判定は変更された履歴のスナップショット差だけを使い、候補表示時は文書ID・セッション・入力世代の定数時間比較とする。移動のたびに全文書の文字ハッシュを計算しない。RapidOCR処理中の古い結果の保護には、これとは別に全編集を追う厳格な世代を維持する。[修正と検証](releases/v1.0.0-dev.235.md)。

## 判定

- 初期条件は基準語3件以上、出現頻度比5倍以上、疑わしい語3件以下。例としてNode.jsが多数、Node.isが少数の場合に後者を候補化する。
- rn/m、vv/w、i/j/l/I/1、o/O/0等のOCR混同を低コストとして扱う。一般的な1文字の挿入・削除・置換、隣接転置も候補化する。削除署名索引で候補を絞り、元の綴りで重み付き距離を確認する。
- 複数の修正先がある場合は距離、登録語、頻度、Ordinal順で代表候補を決め、「ほかの候補あり」と注意する。代表候補が正解とは限らない。
- 任意の「正しい用語」を1行1語／空白区切りで登録すると、出現数が少ない正しい専門語も基準にできる。その語自体を誤認識候補にしない。
- 「選択語を無視」はその綴り全体を候補から除外する。OCRを変更しない。「無視を解除」後に再解析すると戻る。

## 制限と安全性

- 初版は3～64文字・英字2文字以上の英数字技術用語が対象。Node.js、識別子のアンダースコアやハイフンを保持し、大文字小文字を区別する。日本語単語の分かち書き、意味／文脈による正誤判定、全角英数正規化、行・領域をまたぐ単語の連結は未対応。長い識別子を途中で切って候補化しない。
- 同じ頻度の別単語、頻出する誤認識、2文字語などは検出できない場合がある。modeとnodeのように両方正しい語もあるため、必ず原画像で確認する。自動置換はしない。
- 登録語と無視語はこの分析画面を閉じるまでのセッション設定。プロジェクトやアプリ設定には保存しない。
- 既存のOCR／PDF由来の編集用文字列を対象とし、文字のない画像ページには新しいOCR認識を実行しない。修正対象はOCR文字列だけであり、既存可視本文の打ち直し・原画像の修正ではない。
- 全文800万UTF-16文字、10万領域、75万対象トークン、2.5万異なり語（登録語含む）、登録／無視各2,000語、索引35万項目、比較25万組、距離計算3,000万セル、候補1万件が上限。超過は理由を表示し、部分結果を返さず中止する。大きい書籍は分割して分析する。
- 重い比較はバックグラウンドで実行し、キャンセルと文書世代検査を行う。外部サービス・ネットワーク・新しいネイティブ依存は使わない。既存AppContainer内のページ読込経路を維持する。

プロジェクト形式1.11／最小読込dev.206／設定形式21は変更しない。分析スナップショットは画面の一時状態であり、保存形式へ新しい項目は追加しない。

## 共通辞書化の計画記録（dev.242時点、dev.243で上記を実装）

再OCRとの辞書共用、資料別の正解語／補正ルール／無視語の保存、頻度キャッシュ、背景準備・差分更新は[共通OCR補正辞書の実装計画](Shared-OCR-Lexicon-Implementation-Plan.md)に整理した。現行のセッション限定仕様を既に変更したものではない。2026-10-25の利用者回答で、初期は英数字＋登録日本語語句を対象とし、再OCRでの明示許可済み同文字数ルールの自動適用も含めることが確定した。背景集計や通常の一覧表示だけで本文を自動変更する仕様ではない。
