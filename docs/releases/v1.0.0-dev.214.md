# v1.0.0-dev.214 — 目次行の画像自動調整

## 原因と対応

添付例は本文＋長い点線＋末尾ページ番号の目次行。従来は点線も通常の句読点の幅事前値で扱い、その幅を行全体へ正規化していた。累積境界候補をその想定位置付近へ制限するため、実際の点間隔との差が本文へ波及する。1文字ずつ再実行すると起点が更新されるので結果は変わるが、毎回の解析で完全な一致を保証するものではない。

- OCRで同じ点文字（`.`／`．`／`·`／`・`）が8個以上続き、画像でも同数・細い低インク成分・規則的な間隔を確認できた場合のみ、実測点間隔で境界を固定する。
- 点線の前後の本文・ページ番号はそれぞれ独立した幅基準で推定する。濃淡の正規化と平滑化も区間ごとに行い、長い点線で本文の解析尺度が変わらないようにする。
- 回転補正用の画素座標を画素中心の規約に合わせる。従来は`n + 0.5`を偶数丸めして交互の列・行を重複／欠落させ、微小な座標差でも再実行の画素が変わっていた。中心に最も近い画素を一貫して採り、無回転時は元の行・列をそのまま維持する。
- 行頭／行末の「ー」・括弧・全角句読点は、他の字形より薄くても単なる余白として切り捨てない。
- 一般の「行を画像から自動調整」「選択文字以降を画像から自動調整」「一括自動調整」は同じ推定器を使用。既存の文字選択、選択前の固定境界、文字／領域ロック、1回のUndo／Redoを維持する。
- 点線の数が合わない、間隔が不規則、画像の大きな字形しか確認できない場合は従来の推定へ戻す。OCR文字列を自動で書き換えたり、画像中の点を黙って省いたりしない。短い三点リーダー等は今回の点線アンカー対象にしない。
- 解析時の画素コピーは回転した対象領域の外接矩形＋ガードだけとする。ページ全体の管理配列を行ごとに作らない。回転とページ端のクランプを維持し、切り出しでも修正後の全面コピーと同じ画素を採る。逐字的なコマンド反復や永続キャッシュを追加しない。
- 画素が少ない確定済み点線を、通常本文の濃淡基準によって「空セル」と誤判定しないようにする。結果の案内に、実測点線の補正を使ったことを表示する。

## 制限

画像のみからの境界推定であり、完全な字形認識ではない。OCR文字列の誤り、接触した字形、複雑な背景、点数の不一致、点線以外の累積ずれは引き続き手動確認が必要。今回の添付画像は症状確認に使用したが、元のPDF／プロジェクトは受領していないため、実文書そのものの一致は未検証。画像の類型を再現した合成画像と既存回帰で検証する。

プロジェクト形式1.11／最低読込版dev.206、設定形式20、UI配置・アイコン・ショートカットは変更しない。設計書のMarkdown原本を更新し、旧設計PDFは再生成しない。Gitコミット・push・公開は今回の作業に含まない。

診断用の旧エディター試験は隔離した実PDFを準備して文書操作の条件を満たすようにし、OCR描画試験も新しいAvalonDockのLoaded後に実際の編集領域を検査する。通常のアプリ起動やPDF操作に試験処理を追加するものではない。
