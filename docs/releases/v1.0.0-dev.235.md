# v1.0.0-dev.235 — OCR行の位置調整後も類似語修正を継続

## 修正内容

- 類似語を1件修正したあと、PDF上のOCR行を動かすだけで一覧が失効することを修正前の処理で再現した。原因は、文字分析とすべての編集履歴を同じ世代で判定していたことだった。
- 類似語専用の、巻き戻らないOCR入力世代へ分離した。OCR行の位置・幅・高さ・回転・文字送り・読み順・確認状態だけの変更では、分析済み候補を維持する。配置変更だけのUndo／Redo、分析中の配置調整も全体再分析を求めない。
- 文字列変更、領域の追加／削除、行／文字の固定変更、ページ構成・文書セッション変更では従来どおり失効する。文字変更をUndoして同じ文字へ戻しても、古い候補を復活させない。適用直前の原文一致・非重複・実際の固定状態の検査も維持する。
- 残りの候補・選択・並べ替えを保ったまま、移動後の現在の座標へジャンプし、続けて確認修正できる。頻度は分析時の値であり、自動再集計はしない。状態メッセージもこの条件に合わせた。
- 変更のあった履歴だけを分類し、現在性の確認は世代番号比較のままとする。選択・移動のたびの全文比較・画像解析・再認識・一覧再生成は追加しない。RapidOCR処理中の編集拒否には、従来どおりすべての編集を追う別の世代を使う。
- プロジェクト形式1.11／最小アプリdev.206・設定21・外部依存は変更しない。GitHub公開や署名を意味する更新ではない。
