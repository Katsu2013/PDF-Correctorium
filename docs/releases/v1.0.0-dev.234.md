# v1.0.0-dev.234 — 再OCR余白と文字範囲を分離

## 修正

- 余白付き画像の全幅を文字サイズ推定へ渡していたため、特に行端が句読点・長音・括弧のとき、行端保護によって余白まで先頭／末尾セルへ取り込む場合があった。ワーカーで画像の文字画素範囲を別途記録し、その読み方向の範囲だけで文字幅を推定する。余白の中にある実際の句読点は保持し、空白部分は適用しない。
- 行のサイズを更新するたびに切り出しの小数画素位置も変わっていた。回転を解決したページ画素グリッドへ切り出しを固定し、同じ画像・同じ文字で実行を重ねても行端が広がらないようにした。0.001編集画素以内の変換誤差だけを無変更扱いにし、不要なUndo記録を防ぐ。文字訂正や実際の幅変更は引き続き1回でUndoできる。
- 上下の実画像読み取り余白を行高の12%（2〜12px）から30%（4〜32px）へ拡大した。左右は従来の50%（4〜96px）。認識入力の追加白余白も、上下各3pxから準備済み画像高の1/8（整数・6〜16px）へ増やし、左右各2pxは維持する。この白余白も文字配置には含めない。
- 文字幅解析には上下方向の背景を残し、太い文字の黒い部分を背景と取り違えないようにする。適用する行の高さ・回転・読み順・元OCRは保持する。周辺の別行や図が認識範囲へ入る資料では引き続き原画像と候補を確認する。
- 認識は1要求1回、候補1つのまま。モデル・辞書・外部依存・プロジェクト形式1.11／最小アプリdev.206・設定21は変更しない。新規の範囲／ページ／PDF全体OCRは今回の対象外。
