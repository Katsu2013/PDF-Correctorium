# v1.0.0-dev.230 — 選択行のRapidOCR再認識

## 内容

- 日本語モデルを同梱し、横書きの選択行だけをオフラインで再認識。NDLOCR-liteの元データ、文字幅調整、既存の編集モードは維持する。
- 高信頼・一意な挿入だけの文字抜けは自動補完。置換・削除・曖昧な追加・手修正済み文字は原画像と差分を比較して確認する。認識スコアは正答率ではなく、2回の認識の一致だけで正しさを保証しない。
- 位置・寸法・回転・読み順と離れた文字幅を保持。固定中の行・文字は除外。Undoは1操作単位。OCR枠非表示でも補完箇所をマーカーで示す。
- モデルと直近1ページを隔離ワーカーで再利用し、元PDFの隔離コピーは1文書に限定。進捗と中止はステータスバー。読み込み時にOCRやモデル初期化を開始しない。
- 配布先は`components/rapidocr/`、`runtimes/win-x64/native/`、`licenses/RapidOCR/`。他OSのネイティブ資源・既定のラテン語モデル・検出モデル・分類モデル・Pythonは含めない。依存・モデル・辞書のSHA-256を固定する。
- プロジェクト1.11／最小アプリdev.206、設定21は変更しない。既存の保存・PDF出力経路で再認識後の文字を使用する。

## 範囲

今回は横書き1行。縦書き・ルビ付き行、全文OCR、NDLOCR-liteの実行同梱、複数エンジンの多数決は含めない。[操作・判定仕様](../RapidOCR-Line-Recognition.md)。

## 開発中に検出・修正した問題

- 通常の文字列setterによる行幅拡大：文字と送り幅を元外形付きスナップショットとして反映する形へ修正した。
- 大きな白余白による行末の架空文字：自動採用せず検出できていたが、入力の白余白を整えて再認識を安定させた。採用スコアの基準は緩めていない。
- 初期ビルドの診断API名とステータスsetterへのアクセスは既存APIに合わせて修正した。初期の失敗ログは保持する。
