# v1.0.0-dev.254 — ダークメニュー・設定画面・境界色の修正

2026-10-28。dev.253への利用者指摘を受けた修正。以下の配布版検証を完了した開発版。正式公開・署名・Store提出は行っていない。

- PDF／プロジェクトを開いていない状態でも「編集 → 設定」を利用可能にする。「編集」全体の文書依存を解き、編集モード・検索・コメント・墨消しなど文書が必要な子項目には従来の操作制限を保持する。
- メニューのポップアップと右クリックメニューに、アプリの背景・文字・無効文字・ホバー・境界の共通配色を適用する。Windowsがライトでもアプリを明示ダークにでき、開いているメニューも実行時の配色変更へ追従する。
- MenuItem／ContextMenu自体は標準WPFを使用し、入力やメニュー展開の独自処理を追加しない。コマンド、アクセスキー、チェック、クリック時の開閉、入れ子の役割を保持する。動的な最近のファイルも共通スタイルを継承する。
- NDLOCR読込アイコンの固定黒をボタンの前景色へ変更する。有効時は暗い背景で読める色、無効時は無効文字色を使い、形状は変えない。
- メニュー・ツールバー・ステータスバーの区切りを、灰色の1本線へ統一する。ツールバーの横／縦配置に従い線の方向を変える。
- 選択中のツールバーボタンの淡い固定色の外枠をグレーへ変更する。赤い選択マークとアイコンの意味は保持する。
- AvalonDockの固定された明るいパネル枠を共通のグレーへ接続する。対象はドッキング部品の中立色の枠だけで、PDF紙面・OCR・リンク・墨消しの表示へ適用しない。新しい枠のLoaded時とテーマ変更時に反映し、周期的な探索を追加しない。

回帰診断には、文書なしの実設定ダイアログ起動・キャンセル、実際に開く主メニューと右クリック・入れ子メニュー、標準のメニュー項目呼び出し、有効／無効のOCR読込アイコン、区切り線、選択枠、パネル枠を追加した。OSのテーマ設定は変更せず、診断中のポップアップは透明にしてから開き、画像は閉じた後に描画する。
