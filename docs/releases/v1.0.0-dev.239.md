# v1.0.0-dev.239 — ×で閉じたパネルを表示メニューから復元

2026-10-23。製品版`1.0.0-dev.239`、数値版`1.0.0.239`。GitHub公開版の更新ではない。

## 原因と変更

- ×による非表示後のページ一覧／しおりの設定更新が欠けていた。また、レイアウト全体の交換を通知するイベントだけでは、個別パネルのHideを確実に捕捉できなかった。6種類のパネルの標準IsVisibleChangedを監視し、親の付替えが終わった後に1回へまとめて取り込む。ページ・しおり・OCRの表示設定を一括更新し、メニューのチェック・配置XML・保存値を一致させる。
- 非表示パネルの元格納先となる空のワークスペース枠をアプリが削除し、Showが切り離された枠へ挿入したり何もできなくなったりする経路を修正。非表示がある間は元の枠を保護する。既に参照を失った旧配置は、記録された側（独立プロパティは既定の右）へ既存のビューを戻す。細かな旧分割位置を推測して復元するものではない。
- ページ・しおり・OCR／リンク／墨消し／コメント・タグを対象に、メニューから1回で再表示・選択可能にする。機能別サブメニューとモード切替も同じ復元処理を利用する。
- XML復元時には新しいモデルへイベントを再登録し、旧設定の食い違いを修復する。起動だけでは意図的に閉じた機能パネルを再表示しない。明示的な編集モード変更で対応プロパティを開く従来動作は維持する。
- 旧XMLのCanClose／CanHide属性が、再利用パネルを永久削除可能にしたりツールバーを非表示可能にしたりしないようアプリの規約を再適用する。ツールバーの個別ボタンの表示設定は従来どおり。
- 監視対象は6パネルの状態のみ。追加の文書走査・PDF描画・OCR・編集履歴・未保存化は行わない。設定形式21、プロジェクト形式1.11／最小読込dev.206、依存資源は変更しない。

AvalonDock 4.74.1の[LayoutAnchorable](https://github.com/Dirkster99/AvalonDock/blob/v4.74.1/source/Components/AvalonDock/Layout/LayoutAnchorable.cs)と[LayoutRoot](https://github.com/Dirkster99/AvalonDock/blob/v4.74.1/source/Components/AvalonDock/Layout/LayoutRoot.cs)の公開ソースを確認し、標準のHide／Showと戻り先の保持に沿って修正した。内部インターフェースへの反射アクセスやライブラリの変更は行わない。
