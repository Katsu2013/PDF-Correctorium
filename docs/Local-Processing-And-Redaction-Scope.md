# ローカル処理・利用制限・墨消しの範囲

2026-10-30、dev.274の公開準備（前回公開dev.199からの差分）。説明を整理するものであり、文書をクラウドへ送る機能や利用回数の制限を追加する変更ではない。

## 文書処理は完全ローカル

PDF・プロジェクトの読込、描画、OCR校正、同梱RapidOCRによる再認識、検索・分析、保存・PDF出力はPC内で行う。PDF・OCR本文を外部サーバーへアップロードしない。Windowsの読み上げは導入済みのローカル音声を使う。利用状況や障害報告を自動送信する処理も追加していない。

利用者の確定方針は「文書処理は完全ローカル。Webリンク・更新確認は許可する」。次の通信と、文書処理の通信を区別する。

| 操作 | 発生すること | 文書の扱い |
|---|---|---|
| PDFを開く・OCR・保存・出力 | ローカルの処理とファイル書込み | クラウド送信なし。通常の文書処理はネット接続を必要としない |
| Webリンクを利用者が開く | 既定ブラウザーが指定URLへ接続する | 本文の自動アップロードはしない。URL自体に含まれる情報やIPアドレス等は接続先へ渡り得る |
| ZIP版の配布ページを開く | ブラウザーでGitHubを開く | PDF・プロジェクトを送信しない |
| 直接MSIX版の更新確認 | 設定されたHTTPSフィードの版情報を取得する | PDF・OCR本文を要求へ添付しない |
| Store／App Installerの更新 | Windows側の設定・ポリシーに従って確認・ダウンロードする | 文書処理とは別の配布機構。実配布の開始前に署名・導入・更新試験が必要 |

起動しただけで文書を送信する仕様へ変更していない。「外部通信ゼロ」では、利用者が依頼したリンク表示・更新まで行わないように受け取れるため、「文書処理は完全ローカル、文書の外部送信なし」と表記する。

開発者による依存パッケージの取得、公開ソースを使うGitHub Actionsのビルド、署名サービスへのアプリ提出は、利用者がアプリで文書を編集する処理とは別。CIは生成した試験データだけを使用し、利用者のPDFやプロジェクトを試験資源へ入れない。

## 回数・期限・利用料の制限なし

課金による処理回数、使用期限、出力回数の制限は追加しない。一方、破損ファイル・異常な展開量・メモリ消費からPCを守るため、従来から処理上限がある。

| 現行の既定上限の例 | 値 | 超過時に起こること |
|---|---|---|
| プロジェクトのページ数・ページ番号 | 10,000 | プロジェクトの生成・読込等で拒否される |
| プロジェクト内のOCR領域総数 | 200,000 | 読込時の検査で拒否される |
| 1ページのOCR領域 | 10,000 | 同上 |
| プロジェクト内の1つのJSON | 256 MiB | 上限を超える読込・展開を拒否する |
| 内包する元PDF | 16 GiB | 内包元PDFの展開検査で拒否される |
| プロジェクトの圧縮済みサイズ | 18 GiB | アーカイブを拒否する |
| PDF処理ワーカー1プロセスのメモリ | 2 GiB | 資源制限で処理が失敗する場合がある。アプリ全体の使用量を2 GiBに限定する設定ではない |

壊れていない巨大文書でも、この上限やタイムアウトへ達する可能性はある。これは無料枠やライセンス上の制限ではなく、現行実装の制約。上限を撤廃すれば待ち時間・メモリ不足・異常終了の危険が増えるため、無断で撤廃・引上げしない。必要な文書が上限へ達する場合は、分割読込や段階処理等を検討する。

正本は `ProjectPackageLimits`、`ProjectPageSequence.DefaultMaximumPageCount`、`WindowsProcessJob.Attach` 等の実装値。全ての数値を単一の「最大PDFサイズ」として扱わない。

## 墨消しした完成PDFと編集データ

対象範囲の表示や本文文字を出力PDFから除去し、本文文字の残存等を検査してから保存先へ確定する方針を維持する。文字を残して黒い図形だけを重ねる方式へ変更しない。安全に処理できない場合は出力を確定しない。

ただし、指定範囲にある情報と、別の場所に複製された同じ情報は別の対象になる。

- 本文の氏名を墨消ししても、その氏名が文書の作成者欄、しおりタイトル、別ページ、添付された原稿にも存在する場合、それら全てを同一の秘密情報として自動検出・除去する機能ではない。
- 古い構造ツリーや代替文字列による持ち越しを防ぐ処理がある。読み方を出力する場合は、墨消し対象等を除外した安全な範囲だけで読み方情報を再構成する。元のタグ構造の完全維持は保証しない。
- 元PDF、編集可能な `.pdfocrproj`、世代バックアップ、ローカルの作業キャッシュは、復元・再編集のために墨消し前の情報を保持し得る。完成した墨消し済みPDFと同じものとして共有しない。
- キャッシュの保持は外部への自動送信ではない。しかし、アプリの実行フォルダーを丸ごと第三者へ渡すと、そこに残るPDFや履歴も渡してしまう。配布用資源と利用者データを分離する検査を追加した。

「指定範囲の本文を除去し検証する」という実装上の約束と、「端末や文書のどの場所にも秘密が一切残らない」という保証を混同しない。後者を文言だけで満たしたことにはしない。
