# OCR表示と読み込み進捗（dev.228更新）

## 通知の役割

- 通常のリンク確認とPDF特性の確認は下部ステータスバーに表示する。進捗率は読み込み済みの元PDFページ数から算出し、件数不明の特性検査は不確定表示とする。
- ステータスバーのツールチップで、表示ページが編集できるか、保存・出力時に読み込み完了を待つかを確認できる。明示的な保存・出力等の進捗を優先し、その間は通常の読み込み進捗欄を隠す。直前の操作結果は上書きしない。
- 読み込み完了後は進捗欄を隠す。文書の切替に前文書の進捗を持ち越さない。読み込み失敗・編集停止理由や入力PDFの注意事項は上部に残す。
- ステータスバー自体を非表示にした利用者設定は尊重する。進捗のために上部通知を再表示しない。

## 文字と枠の分離

- dev.264では、段落編集の行ごとの枠を段落全体の外枠へ置き換える。全段落を薄く表示し、選択中を強調する。同じ枠表示・不透明度を使い、PDF出力には含めない。[段落枠の仕様](Paragraph-Outlines.md)。
- 既存のOCR表示スイッチはオーバーレイ全体の表示を制御する。
- 新しい「表示 → OCR枠を表示」は、OCRの行／段落／文字セルの枠・塗りと操作ハンドルだけを切り替える。赤文字は残し、クリック・文字選択・キーボード・プロパティによる編集も継続できる。サイズ変更／回転のハンドルは非表示にして、見えないハンドルによる誤操作を防ぐ。
- 非表示時も領域のヒットテストと文字の位置・大きさを変えない。ロック状態・選択状態を変更しない。dev.228以降、検索・品質分析・類似語の「選択箇所へ移動」で一致文字だけに半透明の黄色マーカー（アルファ40%）を描く。これは通常のOCR枠・塗りではなく移動先の目印であり、枠非表示・枠不透明度0%でも表示する。赤い検索枠は非表示に従い、文字の強調とマーカーは維持する。読み順編集モード固有の番号バッジは独立した表示である。
- マーカーは現在の一致範囲だけに表示し、次の結果へ移動すると既存の共通処理で切り替える。検索強調の解除や対象文字の編集で消える。縦書き・結合文字・サロゲート対も既存の文字セル境界を使用し、行全体を塗らない。通常の選択・ロック状態を強制表示するものではない。
- アプリ設定の「表示 → OCRオーバーレイ」に表示チェック、不透明度0〜100%、プレビューを置く。不透明度は既存の枠・塗りのアルファ値に掛ける係数で、初期値45%。元々半透明の塗りが100%で完全不透明になるわけではない。赤文字にはこの係数を掛けない。操作ハンドル自体の薄さは既存の専用設定を維持する。
- 設定はアプリ全体で保存し、再起動・設定移出入で保持する。設定形式21で任意フィールド `ShowOcrFrames`、`OcrFrameOpacity` を追加。旧形式ではtrue／0.45を補い、非有限値は0.45、範囲外は0〜1へ正規化する。プロジェクト互換形式を上げない。

## 性能・データ安全性

表示設定の変更でPDF再描画・OCR再読込・全ページ走査・文書履歴追加を実行しない。既存の文字セル／字形キャッシュを再利用し、枠の描画部分だけに不透明度を適用する。プロジェクト未保存状態、元PDF、墨消し、リンク枠、PDF出力内容に影響させない。上部通知の移動でもドッキングパネルを作り直さない。

## 回帰検証

`--ocr-rendering-test` で文字のみのピクセル比較、枠アルファ、実画面の非表示・ヒットテスト・ハンドル・セル再利用・未保存状態を確認する。`--settings-test` で移行、正規化、保存・再読込・移出入、日英UIを確認する。`--link-editing-test` で通常進捗の下部表示と失敗時の上部表示を確認する。完了した検証結果はリリースノートに記録する。
